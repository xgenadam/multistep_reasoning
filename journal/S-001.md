## What went wrong

- First read of `OBJECTIVE.md` failed: file was mode 0600 owned by uid 1001
  (`dsh`) while the agent runs as `ubuntu` (uid 1000); `sudo` is blocked
  (no-new-privileges in the container). Resolved by the user fixing
  permissions out-of-band.
- No other code was read before the first opinion pass — the opinion was
  given on the doc's own audit; the verification pass came after. The right
  order would have been verification first, opinion second. Cheap here
  because the audit happened to be accurate.

  days); Phase P parallel to B. *(Promoted: see PLAN.md phase map.)*

  siblings (P-P4 requires recovery, not just detection).
- Layered `VerifierSpec` from day one (objective / llm_judge / fol) with
  confidence-tiered verdicts.
- Chat memory: stack, don't replace (rolling summary stays in-prompt).
- Tickets = markdown files in `journal/tickets/`, no server; graduation
  triggers written down (two-human parallelism or ~30–50 active items).
- AAR will be mechanical synthesis of S-entries + criterion outcomes +
  git log; no separate writing exercise.
