## What went wrong

- The plan assumed a Python 3.13 venv. `instructor==1.3.*` cannot install on
  3.13 (`jiter<0.5`, no cp313 wheel, PyO3 0.21 build fails). Pinned to 3.12.
- `uv venv --python python3` silently chose uv's managed 3.12.15 instead of
  `/usr/bin/python3` (3.13.5) — the first green run was on 3.12 without my
  noticing until `--version`. The Makefile now names the version.

## Pain points and how they were solved

| Pain | Cause | Resolution | Left a durable fix? |
| --- | --- | --- | --- |
| No interpreter in container | venv built for 3.12 elsewhere | `make venv` (uv, managed 3.12) | Yes — Makefile + pyproject |
| 3.13 build failure | old instructor → old jiter | `requires-python <3.13` with a comment naming the cause | Yes, until the instructor upgrade |
| Env var silently beating `--base-url` | D-P order puts env first | harness exits 2 when both are set and differ | Yes |
| Harness module import in tests | dataclasses need `sys.modules` entry | register before `exec_module` | Yes (in the test) |

## Decisions made

- **Python 3.12 only** (`>=3.12,<3.13`) until a ticket upgrades instructor
  past 1.3; that ticket also lifts the cap. Deviation from O-3's "3.13";
  O-3 counted as passed with this recorded. O-01 promotes it to
  DECISIONS.md.
- D-P precedence fixed as `LLM_BASE_URL` → launcher config dict → explicit
  `base_url` → `host`+`port` → `ValueError`.
