## Scope

Phase 0 item 2 / defect D3: the op set (`operations.py`) has
`add_part, append_to_part, replace_in_part, insert_in_part, update_part,
move_part, delete_part` but no way to **merge** — so the composer's only
dedupe tool is delete-and-re-add, which loses provenance and op-log
integrity. Add a `merge_parts` op:

- Schema: `{id, kind, title?, ids: [source ids], after}`.
- Semantics: concatenate source bodies **verbatim** in the given order,
  insert the new part, delete the sources.
- Implementation: schema model + `_apply_one` case in
  `document/apply.py` (alongside the existing ops at operations.py:66-72).
- **Unit tests are in scope here** (pure state manipulation; the phase gate
  is still behavioral): happy path, empty ids list, id not found, source
  appears twice in ids, `assert_payload_kept` interaction (a merge dropping
  the current sub-task's result must still raise).
- `changed_part_ids` already feeds deleted ids into the summary update —
  verify the merge path exercises that (see 0-07).

This op unblocks Phase P's snapshot design (merge semantics the DAG
frontier needs) and is the primary tool for the P0-3 dedupe rule.
