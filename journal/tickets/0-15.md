## Scope

Source: S-007 (user request, 2026-10-19), D-013, defect N20. This must land
before 0-16, so the baseline knows which thinking setting it measured. It
follows 0-14 because both edit `harness.py`. Do not hoist instructor (see
AGENTS.md § What this repo is).

1. **Switch** (`reasoning_sub_agents/config/schema.py`, `llama_utils.py`):
   - `options.thinking: off | on` (default `off`), plus optional
     `options.thinking_by_step` keyed by step kind (`decompose`,
     `decompose_critique`, `executor_turn`, `oracle`, `compose`,
     `consolidate`, `summary`). Reuse 0-14's kinds; don't invent a second
     set.
   - One helper builds `extra_body={'chat_template_kwargs':
     {'enable_thinking': …}}`, and all three call sites (instructor create,
     the non-instructor JSON retry, `stream_conversation`) pass it. The step
     comes from a ContextVar set alongside `llm_step`, the same way
     `prompt_logging` works.
   - Servers that reject `chat_template_kwargs` would also fail on the old
     code with a strict server. Record the fact if one does; don't add a
     silent fallback.
2. **Capture** (one helper in `llama_utils.py`):
   - Non-streamed: `message.reasoning` or `message.reasoning_content`. On the
     instructor path, read them from `response._raw_response` (1.3.2 attaches
     it; check).
   - Streamed: accumulate `delta.reasoning` / `delta.reasoning_content`.
   - Fallback for servers without a reasoning parser: strip a leading
     `<think>…</think>` from `content` *before* the JSON parse, and log it as
     reasoning.
   - `reasoning_tokens` from `usage.completion_tokens_details` when present.
3. **Sink:**
   - A `thinking_log` ContextVar holds records `{ts, turn_id, step, kind,
     setting, reasoning_tokens, chars, text}`. It is never read by any prompt
     builder, the summary or the composer.
   - `options.log_thinking: off | jsonl` (default `jsonl` when thinking is
     on), `options.thinking_log_dir` (default `runs/thinking/`, which the
     root `/runs/` rule ignores). One file per orchestrator turn:
     `<date>/<turn-id>.jsonl`.
   - Harness: per-call `reasoning_tokens` and `reasoning_chars`, per-kind
     sums in `llm_stats`, and the setting in the run-file header. Excerpts
     capped at 500 chars per call (tickets/README rule 8), full text in the
     side log. `--thinking off|on` overrides the YAML.
4. **Tests** (fake client, no server): switch on every call path, each
   capture shape, `<think>` stripping before parse, and "reasoning absent
   from every later prompt" with thinking `on`.
5. **Live check** (`:8091`, `LLM_MODEL=qwen3.8-flash-next`, or `:5000` if the
   27B is loaded; record which): s1 smoke with `--thinking off` and `on`, per
   P0-10. Commit both run files.

Out of scope: showing thinking in the oobabooga UI (0-11 / Phase R), and
choosing per-step `on` defaults (a measured follow-up after 0-16).

- 2026-10-19 (S-009): built as scoped.
  - **Switch.** `progress.STEP_KINDS` holds 0-14's seven kinds, and every
    pipeline `llm_step` names one (`llm_step(label, kind)`, which resets
    on exit). The config's `StepKind` literal mirrors it, and a test pins
    it. `llama_utils.thinking_session(options, turn_id=…)` wraps each
    `iter_query`, next to `prompt_logging`. `thinking_extra_body()`
    goes on all three call paths. Calls outside a turn send `false`, not
    the server default.
  - YAML 1.1 reads a bare `off`/`on` as a boolean, so the options
    validators map `True`/`False` to `on`/`off`.
  - **Instructor path (D-015).** The ticket's `_raw_response` route
    (checked) cannot do the job in 1.3.2:
    - it holds only the last attempt;
    - it is absent for `list[...]` models, so the decompose call would
      log nothing;
    - instructor replaces `usage` with a summed copy that drops
      `completion_tokens_details`;
    - its JSON mode parses from the first `{` to the last `}`, so a
      `<think>` block with braces breaks the parse.

    So `_get_streamed_json_response_inner` builds per request what
    `from_openai` builds, with `create` wrapped by
    `_reasoning_capture`. That logs every attempt and strips the block
    before instructor parses. The seam is unchanged; the seam tests
    pass, and AGENTS.md's invariant is reworded.
  - **Capture.** `message_reasoning` reads `reasoning_content` /
    `reasoning`, including pydantic extras. `split_reasoning` moves out a
    leading `<think>…</think>`; an unterminated block counts as all
    reasoning. `extract_content` / `extract_message` drop the block too,
    so a no-parser server's streamed reasoning never reaches the summary
    or critique. The open-tag-less form (a template that injects
    `<think>` into the prompt) is not handled: neither server here needs
    it.
  - **Sink.** One JSONL per turn at
    `<thinking_log_dir>/<UTC date>/<turn id>.jsonl`, written lazily, so
    a turn with no reasoning leaves no file. The harness names turns
    `<run start>_<scenario>#r<n>:t<i>`, and the run header records
    `thinking.started_at` to link the two.
  - **Harness.** Each record gets:
    - `thinking`, the switch as sent, read from the request kwargs at
      the seam;
    - `reasoning_tokens`, `reasoning_chars` and a 500-char
      `reasoning_excerpt`.

    `llm_stats` gains `thinking_calls`, `calls_without_switch` and the
    per-kind sums. `--thinking off|on`, default `off`, builds the
    options; the harness never read the YAML.
  - **Tests.**
    - `tests/test_llama_utils/test_thinking.py`: 20 tests covering each
      path's switch, the per-step override, and each capture shape on
      each path, including every-attempt and `list[...]` capture.
    - `tests/test_baseline/test_harness_thinking.py`: 5 tests running
      the real orchestrator with thinking `on`. A marker in every reply's
      reasoning is absent from every later request body, the summary and
      the parts.
    - `test_rescore_tracked_runs.py` now splits legacy from fresh run
      files; these two are the first fresh ones.
- 2026-10-19 (S-009): live check on `:8091` vLLM `qwen3.8-flash-next`
