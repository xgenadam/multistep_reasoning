## Scope

Source: D-018 and the user's answers to A-01 § 7.3 and § 7.4 (S-017,
`tickets/A-01.md` Notes). Design only, no code. It does not gate
A-02…A-05. Its implementation needs a corpus store (V) and the judge
(Q-01), so implementation tickets come after those.

Write `journal/design/A-06-retrieval-judgement.md` covering:
- **When to search, and how hard.** Searching is the model's call: it
  searches when unsure, not by reflex, and escalates by tier (working →
  conversation → corpus → derived). Design the confidence signal the user
  floated:
  - what it is and where it comes from (self-report, a verifier tier per
    D-010, retrieval agreement, something else);
  - how it maps to search depth (no search, which tiers, `k`, `search`
    vs `ask`);
  - its prompt cost against the 0-16 denominators.
- **Which source wins.** The tier order in D-018 is the provisional
  default. Say when context overrides it, worked through at least:
  - **book continuity:** the draft deliberately changes a canon fact (a
    character cuts their long hair many chapters in). The working draft
    wins for the continuation, and the divergence is recorded, not
    "corrected";
  - **research:** a working assumption that later work builds on is
    contradicted by a corpus source, or by a derived note from another
    session. The model has room to judge, flags it, and may revise.
- **Escalation.** When a conflict warrants more than an annotation in
  `Answer.conflicts`, for example starting a fresh decompose → execute →
  compose run on the disputed question. Cover the trigger, the cost and
  depth bound, how the result re-enters the working tier, and what the
  user sees. Relate this to R's milestone loop and P's DAG rather than
  inventing a parallel mechanism.
- **How it is tested:** the criteria an implementation ticket will be held
  to, building on V-5 and Q's judge (conflict cases in Q's qualitative
  set).
- **Constraints:** the D-018 interface stays as it is unless the note says
  why it must change; D-011 (no separate memory system); D-010 confidence
  tiers.

The user approves the note (A-10). Record the approval as a dated Notes
