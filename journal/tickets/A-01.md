## Scope

Source: PLAN.md § Phase A, D-001 and D-004. This is the most load-bearing
design in the plan; every later store sits behind it.

Write `journal/design/A-01-context-store.md` (new directory) containing:
- **The interface:** `ContextStore{store_id, list(filters), read(id, start,
  end), search(query, k, filters) -> list[Hit], ask(question, k),
  summary(id)}`, and `Hit{store_id, doc_id, chunk_id, title, span, score,
  text, provenance}`. Declare a write-side method (D-004) but do not
  implement it.
- **The conflict policy:**
  - working memory outranks corpus for current-task questions;
  - cross-store conflicts are annotated, never silently resolved;
  - every citation carries a store id.
- **The dry-run (A-9):** walk every method through five store kinds:
  - document (today's oracle);
  - papers (sections, citation edges);
  - books (chapters, canon);
  - code (symbols, call edges);
  - notes/chat.

  Per method, record "fits" or the change made.
- **Mapping to today's code:** `oracle/tools.py`, `DocumentOracle`,
  `SearchHit` (no store id or score today), and where `context/` sits
  beside the existing layout (no rename, D-001).

The user approves the note before A-02 starts. Record the approval as a
dated Notes bullet.
