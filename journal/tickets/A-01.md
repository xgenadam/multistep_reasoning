## Scope

Source: PLAN.md § Phase A, D-001 and D-004. This is the most load-bearing
design in the plan; every later store sits behind it.

Write `journal/design/A-01-context-store.md` (new directory) containing:
- **The interface:** `ContextStore{store_id, list(filters), read(id, start,
  end), search(query, k, filters) -> list[Hit], ask(question, k),
  summary(id)}`, and `Hit{store_id, doc_id, chunk_id, title, span, score,
  text, provenance}`. Declare a write-side method (D-004) but do not
  implement it.
- **The conflict policy:**
  - working memory outranks corpus for current-task questions;
  - cross-store conflicts are annotated, never silently resolved;
  - every citation carries a store id.
- **The dry-run (A-9):** walk every method through five store kinds:
  - document (today's oracle);
  - papers (sections, citation edges);
  - books (chapters, canon);
  - code (symbols, call edges);
  - notes/chat.

  Per method, record "fits" or the change made.
- **Mapping to today's code:** `oracle/tools.py`, `DocumentOracle`,
  `SearchHit` (no store id or score today), and where `context/` sits
  beside the existing layout (no rename, D-001).

The user approves the note before A-02 starts. Record the approval as a
dated Notes bullet.

## Notes

- 2026-10-19 (input from the user in S-008, before this ticket starts): the
  document plays different roles. In a chat turn it is effectively the
  reply, which the next turn need not preserve. In a coding turn (or a
  report under revision) it is the artifact, whose parts and ids must
  persist. The user proposed separate documents: one for new responses and
  one acting as short-term memory.
  - **Evidence:** every tracked s3 follow-up adds scratch parts
    (`review-existing-structure`, `structural-review`) and deletes them
    before the turn ends. The model is using the document as a scratchpad
    because it has none.
  - **Sketch from S-008, not a decision:** three kinds, each a store behind
    the door. They are artifact (persistent, patched, stable ids), reply
    (per turn, rebuilt freely, becomes history) and working memory (scratch
    + rolling summary, never rendered).
  - **Constraints:** D-011 forbids a *separate* memory system, though a
    store behind `ContextStore` is allowed. D-014 currently holds only
    artifact follow-ups to part identity. Walk the three kinds through the
    A-9 dry-run.
