## Scope

Source: PLAN.md § Phase 0 close-out, N18, D-007. This is a two-stage ticket,
one stage per session.

**Stage 1, run (Sonnet 5.5 / low):**
- Run s1–s4 × 2 with `--jobs 1` on post-0-14 labels, in a genuinely idle
  window. Claim the server in INDEX before starting and release it after.
  The session must not call the model while the run is going: start it in
  the background and wait for it.
- `--label rebaseline-0-16`.
- `compare.py`'s contamination check must accept every run; a rejected run
  is redone.
- Commit the run file(s) with a dated Notes bullet.

**Stage 2, analyse (Opus 5.5 / high):**
- New denominators per scenario: wall time, compose p50, decompose-pair
  p50, executor-turn p50, and prompt/completion tokens per turn.
- They replace AGENTS.md § Baseline, and INDEX gets a one-line pointer.

  265–432 K per turn vs a pre-change median ≈ 80 K) by call kind. Candidates
  are composer `need_part_ids` fetches, extra oracle rounds and
  regeneration.
- Decide fix-or-accept and append the decision to DECISIONS.md.
  - A fix that is a prompt redesign is its own ticket; its design runs on
    Fable / high.
  - If the fix lands before A, re-baseline again (D-007).

## Notes

- 2026-10-19 (S-008, from 0-14; handoff, not work on this ticket):
  - **Contamination gate.** `check.py <run>` prints `timing: clean |
    CONTAMINATED` per turn. That is the per-run form of compare.py's rule.
    Its yardstick, `compare.CLEAN_COMPOSE_P50_S = 18.0`, is S-002's 27B
    number. Replace it with this ticket's measured compose p50, and only
    run against the generator it was measured on.
    - The compose-only proxy flags s3 follow-up turns, where compose sees a
      grown document (0-14 Notes). Use a per-turn yardstick for multi-turn
      scenarios, or accept the noise and say so.
  - **P0-3 on s3.** The re-run s3 is the first fresh run scored by the
    P0-3 part-identity check (D-014). Both tracked rebuild follow-ups fail
    it: each drops turn 0's part and re-adds the text under a new id (0-14
    Notes). Watch that row.
- 2026-10-19 (S-009, from 0-15; handoff, not work on this ticket):
  - **Thinking.** `harness.py --thinking` defaults to `off`, which is the
    D-013 baseline setting, so do not pass `on`. Each run file's
    `thinking` header records the setting, and `check.py`'s Run line
    prints it. `calls_without_switch` must be 0. A run whose header says
    `unrecorded (pre-0-15)` predates the switch and is not a baseline.
  - On `:8091`, s1 with thinking `on` took 356 s against 59 s with `off`,
    and 39.9 K completion tokens against 5.7 K. Those are single points
    (0-15 Notes). Measuring `on` is a separate comparison after this
    ticket.

- 2026-10-19 (S-010, stage 1 done; stage 2 still open): ran s1, s1b, s1c, s2, s3, s4 x2
  with `--jobs 1 --label rebaseline-0-16`, thinking `off`, on `:8091`
  (`qwen3.8-flash-next`, vLLM; the 27B on `:5000` was not loaded). The server
  was idle at the start (0 running, 0 waiting) and the session made no model
  calls during the run. `check.py` prints `timing: clean` for all 14 turns and
  attribution is exact (227 calls, 0 unattributed). Four turns fail
  behavioural checks, which stage 1 does not act on:
  - P0-1 (prose parts in a code task): s1 r1, s1b r0, s1b r1.
  - 0-09 (file body pre-fenced): s1b r0, s1b r1, s1c r1 (the 0-09 fix does not hold on this model).
  - P0-3 on s3 t1: both runs PASS (no prior part dropped).
- The yardstick `compare.CLEAN_COMPOSE_P50_S = 18.0` is S-002's 27B number. Compose
  p50 here is 2.0-2.6 s per turn, so it cannot flag contamination on this
  generator. Stage 2 replaces it.
