## What went right

- **The bench was written in reviewed batches by sub-agents against one brief.** It covers 140 prompts: 70 code with hidden tests, references and broken variants, and 70 report prompts with checklists. Every batch passed `check-bench` before commit, and `test_bench_v1.py` caught the one stray (r06f's delivery line). It was frozen at `8e5cede` before any tracked run file.
- **D-022 let stage 0 finish in one session.** The agent proceeded on its own recommendations, marked everything provisional, and listed every point for the user's mass review (design note § 9). The pre-registration was committed before the first tracked run file, as Q-6 requires.
- **The pilot was stratified once the first numbers showed why.** On flash-next, long reports came out at 3.4–4× and short ones far under. Adding c42 and r38 gave every domain × length stratum three prompts, and the same 12 prompts were then piloted on all three generators. The result is consistent across them: the domain-level N cannot match on any generator.
- **The watchdog worked as designed.** At 13:50Z it stopped both generators before either baseline wrote a file. The agent left the halt flag in place until the user had capped the cards at 280 W, then cleared it with the reason logged. The rest of the GPU work ran one generator at a time on four cards, peaking at 83 °C (GPU1, the 27B at `--jobs 3`).
- **D-023 (the user's confidence-study request) was built as logging only.** `rounds` holds every draft and critique, and prompts, N and outputs are unchanged. It was tested, and the study itself is planned (Q-07, criterion Q-12) and not built.

## What went wrong

- **The side-by-side layout of the two llama.cpp generators tripped the watchdog.** The dense 27B on two cards drew ≈ 300 W per card, and GPU1 ran hot. About 30 minutes of GPU time were lost, but no data, since no run file had been written. On this box's cooling, the 27B needs four cards (or a lower cap).
- **The agent's heat-alert loop never terminated.** `pgrep -f "harness.py|arms.py run"` matched the loop's own command line. It was harmless, since it only watched, and was fixed with the `[h]arness.py` bracket idiom.
- **The flash-next baseline recorded its commit at write time**, after bench batches had landed mid-run. Provenance was reconstructed in Notes. Both drivers now read the commit at start and record `commit_at_end`.
- **The IFEval half of the standard slice is unscored.** Fetching and installing Google's checker was blocked as untrusted code integration. That was correct to stop on, and the choice is the user's.
- **The first draft of the review note stated a Holm-corrected power, "about 70 %", without computing it.** It was ≈ 60 % and was corrected before commit. Numbers in notes are computed, never estimated in passing.

- **A second watchdog trip (21:34Z) exposed two gaps.**
  - The stop step missed a llama-server that had outlived its container
    record. It kept running for 9 minutes. The watchdog now also kills GPU
    processes by PID.
  - The trip itself was a single-sample hardware-slowdown flag that left
    0 µs in the driver's counters. The watchdog now needs two samples in a
    row, or growth in the counters.
- **The clearing of the halt flag was blocked by the permission check**
  until the user said so explicitly. That was the correct outcome: the
  agent asked, and did not route around it.
- **The speed-check script lost two 35B-A3B configurations.** A crashed
  server held its port longer than the script waited. Fixed by waiting for
  a bindable port.

## Pain points

| Pain | Cause | Resolution | Durable fix? |
| --- | --- | --- | --- |
| A config typo would change nothing silently | pydantic ignores unknown keys | `apply_overrides` checks every path against the model's fields | yes |
| The watchdog could not find GPU containers by device | nested podman records no device in `inspect` | match by name, and by `NVIDIA_VISIBLE_DEVICES` in the image environment | yes |
| llama.cpp sends no `reasoning_tokens` | server behaviour | reasoning counts only inside `completion_tokens`, which is what Q-7 matches on | n/a |
| GPU1 runs hottest under any dense load | the card's position or cooling | the 280 W cap set by the user; one generator on four cards | not persistent across a host reboot (the user's choice) |
| The domain-level (a″) N cannot match compute | rounds cost differs by length and generator | two amendments proposed in Q-02 Notes | waits on the user |
| A self-matching `pgrep -f` | the pattern appears in the watcher's own argv | the `[x]` bracket idiom | yes, as practice |
