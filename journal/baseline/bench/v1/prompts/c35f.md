Extend the `tmpl` package with template inheritance, loaders and HTML autoescaping. Everything from the previous version keeps working exactly as before; a template that uses none of the new features renders the same as it did.

## Loaders and environments

- `tmpl/lexer.py` adds `class TemplateNotFound(TemplateError)`, constructed as `TemplateNotFound(name: str)`, with the attribute `name` and `str(error) == f"template not found: {name}"`.
- `tmpl/render.py` adds `class DictLoader`: `DictLoader(templates: dict[str, str])` maps template names to their source text, and `get_source(name: str) -> str` returns a template's source or raises `TemplateNotFound(name)`. Any object with a `get_source(name)` method of that kind can serve as a loader.
- The constructor becomes `Template(source: str, *, loader=None, autoescape: bool = False, name: str | None = None)`, keeping the attributes `loader`, `autoescape` and `name`. `Template(source)` behaves as before.
- `tmpl/render.py` adds `class Environment`: `Environment(loader=None, autoescape: bool = False)`.
  - `get_template(name: str) -> Template` loads the source from the loader and returns `Template(source, loader=..., autoescape=..., name=name)` with the environment's loader and autoescape setting. It raises `TemplateNotFound(name)` when the loader has no such template or there is no loader, and `TemplateSyntaxError` when the source is malformed.
  - `from_string(source: str) -> Template` does the same for a source string, with `name` left as `None`.
- `tmpl/__init__.py` also exports `TemplateNotFound`, `DictLoader` and `Environment`.

## Inheritance

- `{% block NAME %}...{% endblock %}` (or `{% endblock NAME %}`) marks a named, overridable region. `NAME` follows the variable name rule. Blocks may nest. In a template that does not extend another, a block simply renders its contents in place.
- `{% extends "name" %}` (single or double quotes) makes the template a child of the named parent. It must be the template's first tag: only whitespace text and comments may come before it. When a template extends another, rendering it renders its parent instead, with the same context, and every block in the parent is replaced by the child's block of the same name if the child has one. Everything in the child outside its blocks is ignored when rendering (it must still be valid syntax). A block the child defines wherever it appears in the child (also inside `if` or `for`) counts as defined. A child's block whose name the parent never renders is not output.
- Chains of any depth work: when several templates in the chain define a block, the definition in the most derived template wins.
- `{{ super() }}` (whitespace allowed inside the braces and parentheses) may appear only inside a block. It outputs the next less derived definition of the enclosing block, rendered in the same context; that definition may itself call `super()`. `super` becomes a reserved word.
- Parents are loaded through the rendering template's loader when `render` is called, using `get_source`.

### New errors

Syntax errors, raised by `parse` and the `Template` constructor (the line rules are the same as before):

- an `extends` that is not the first tag, or whose argument is not one quoted name: the line of the `extends`;
- a `block` without exactly one valid name, or a second block with the same name in one template: the line of that `block` tag;
- a `block` still open at the end of the template: the line of the `block`; an `endblock` with a name different from the block it closes, or an `endblock` that does not close the innermost open block (for example one reached while a `for` or `if` inside the block is still open): the line of the `endblock`;
- `{{ super() }}` outside every block: its line; any other use of `super`: the line of the tag.

Errors raised by `render`:

- `TemplateNotFound(name)` when a parent is missing from the loader, or the template has no loader;
- `TemplateRenderError` when the chain would load a template a second time (for example `"a"` extends `"b"` and `"b"` extends `"a"`, or a template extends itself). Its line is that of the `extends` tag that names the repeated template. A template's own `name` counts as loaded from the start;
- `TemplateRenderError` at the `super()` tag's line when there is no less derived definition of the block;
- a `TemplateSyntaxError` in a parent's source, raised as it is.

## Autoescape

- Autoescaping is off unless `autoescape=True`. When it is on, the output text of every `{{ }}` is HTML-escaped after all of its filters have run, exactly as `html.escape(text, quote=True)` does: `&` becomes `&amp;`, `<` becomes `&lt;`, `>` becomes `&gt;`, `"` becomes `&quot;` and `'` becomes `&#x27;`. Template text outside tags is never escaped.
- A new filter `safe` (no argument) returns its value unchanged. When `safe` is the last filter of a `{{ }}` expression, its output is not escaped. If another filter follows `safe`, the output is escaped as usual.
- A new filter `escape` (no argument) returns the value's output text HTML-escaped as above, whether autoescaping is on or off. When `escape` is the last filter, autoescaping does not escape that output a second time.
- The output of `{{ super() }}` and of blocks is already rendered template output and is never escaped again (the `{{ }}` tags inside them are escaped once, by the rule above).
- The whole render, parents included, uses the `autoescape` setting of the template whose `render` was called.

For example, with

```
loader = DictLoader({
    "base.html": "<title>{% block title %}Site{% endblock %}</title>\n<main>{% block body %}{% endblock %}</main>\n",
    "page.html": '{% extends "base.html" %}{% block title %}{{ title }} - {{ super() }}{% endblock %}{% block body %}<p>{{ text }}</p>{% endblock %}',
})
env = Environment(loader=loader, autoescape=True)
```

`env.get_template("page.html").render(title="Q&A", text="1 < 2")` returns `"<title>Q&amp;A - Site</title>\n<main><p>1 &lt; 2</p></main>\n"`.
