Write the core of a tiny HTTP/1.1 web framework as the package `web/`, with no sockets: it turns the raw bytes of one request into a response's bytes. There are four files: `web/__init__.py`, `web/request.py`, `web/router.py` and `web/middleware.py`.

## `web/request.py`: messages and parsing

**Errors.** `HTTPError(Exception)` has the attributes `status: int` and `reason: str` (the reason phrase from the table below). `BadRequest(HTTPError)` has status 400; its constructor takes an optional message.

**Reason phrases:** 200 `OK`, 201 `Created`, 204 `No Content`, 400 `Bad Request`, 401 `Unauthorized`, 404 `Not Found`, 405 `Method Not Allowed`, 500 `Internal Server Error`; any other status uses `Unknown`.

**`Headers(pairs=())`**: an ordered, case-insensitive multi-map of header fields, built from `(name, value)` pairs. Names keep the case they were given; look-ups ignore case.
- `add(name, value)` appends a field, and `set(name, value)` replaces every field with that name by a single one (at the position of the first, or at the end if there was none).
- `get(name, default=None)` returns the first value; `h[name]` does the same but raises `KeyError`; `get_all(name)` returns every value in order (`[]` if none).
- `name in h`, `len(h)` (the number of fields) and `items()`, the list of `(name, value)` pairs in order.

**`Request`** is a dataclass with the fields `method: str`, `target: str`, `path: str`, `query_string: str`, `version: str`, `headers: Headers`, `body: bytes`, and two dicts that default to empty: `params` (filled by the router) and `state` (free for middleware to use). `target` is the request target as sent, `path` the part before the first `?` (not decoded), `query_string` the part after it (`''` if there is no `?`).
- `query` (property) → `dict[str, list[str]]`: the query string split on `&`, empty pieces skipped. Each piece is `name=value` split at the first `=`, or just `name` with value `''`. In names and values, `+` means a space and `%XX` is a percent-escape; the decoded bytes are read as UTF-8. A `%` not followed by two hex digits, or bytes that are not valid UTF-8, raise `BadRequest`. Values are listed in order for each name.
- `content_type` (property) → `(media_type, params)`, parsed from the `Content-Type` header: the value is split on `;`; the first piece, stripped and lower-cased, is the media type; every other piece `name=value` is stripped, its name lower-cased, its value stripped and freed of one pair of surrounding double quotes; pieces without `=` are skipped, and the first occurrence of a name wins. Without the header: `('', {})`.
- `text()` decodes the body with the `charset` parameter of `Content-Type`, or UTF-8 by default. `json()` parses `text()` as JSON and raises `BadRequest` if it is not valid JSON.

**`Response(status=200, headers=None, body=b'')`** is a dataclass (`headers` defaults to a new empty `Headers`).
- `Response.text(s, status=200)` (class method) encodes `s` as UTF-8 with `Content-Type: text/plain; charset=utf-8`.
- `Response.json(obj, status=200)` uses `json.dumps(obj, separators=(',', ':'), sort_keys=True)`, UTF-8 encoded, with `Content-Type: application/json`.
- `to_bytes()` serialises it: the status line `HTTP/1.1 <status> <reason>`, then each header as `Name: value` in order, then `Content-Length: <len(body)>` as the last header (any `Content-Length` already present is dropped), then an empty line and the body. Every line ends with `\r\n`.

**`parse_request(data: bytes) -> Request`** parses exactly one request; anything wrong raises `BadRequest`:
- The head is the bytes before the first `\r\n\r\n` (none: `BadRequest`), decoded as ISO-8859-1 and split on `\r\n`.
- The request line is `METHOD SP target SP version`, with exactly two single spaces. The method is one or more ASCII uppercase letters; the target starts with `/`; the version is `HTTP/1.1` or `HTTP/1.0`.
- Each header line is `name:value`. The name is one or more of the token characters `A–Z a–z 0–9 ! # $ % & ' * + - . ^ _ ` | ~` and is followed directly by the colon; the value has its surrounding spaces and tabs removed. A line that starts with a space or tab (obsolete line folding) is an error.
- `HTTP/1.1` requests must have a `Host` header.
- The body: if `Transfer-Encoding` is present, it must be `chunked` (any case), and `Content-Length` must not also be present. Chunked data is a series of chunks, each a hex size (optionally followed by `;` and an extension, which is ignored), `\r\n`, that many bytes, `\r\n`; a chunk of size 0 ends the data, followed by optional trailer lines (ignored) and an empty line. Otherwise, if `Content-Length` is present it must be decimal digits only; several `Content-Length` fields must all hold the same value; the body is exactly that many bytes, and fewer bytes is an error. With neither header the body is empty.
- Bytes left over after the body are an error.

## `web/router.py`

`NotFound(HTTPError)` has status 404. `MethodNotAllowed(HTTPError)` has status 405 and an attribute `allowed`, the sorted list of methods the path does accept.

`Router()`:
- `add(method, pattern, handler)` registers a handler, called as `handler(request) -> Response`. `route(pattern, methods=('GET',))` is the same as a decorator that returns the function unchanged.
- A pattern is `/` or a `/`-separated list of segments, each a literal, `{name}` (one non-empty segment, as a `str`), `{name:int}` (one segment of ASCII digits only, converted to `int`) or `{name:path}` (the rest of the path, one or more segments, kept joined with `/`; allowed only as the last segment). `ValueError` if the pattern does not start with `/`, repeats a parameter name, uses an unknown converter, puts `path` before the end, or if the same method and pattern string are already registered.
- Matching: the request path, without its leading `/`, is split on `/` and then each segment is percent-decoded with the same rules as the query string except that `+` stays a `+`. An encoded slash `%2F` is therefore part of one segment, not a separator. A literal matches a segment equal to it after decoding. A trailing slash matters: `/users/` has an empty last segment and does not match `/users`; no parameter matches an empty segment. Patterns are tried in the order they were registered and the first match wins. Bad escapes raise `BadRequest`.
- `resolve(method, path) -> (handler, params)`. If no pattern matches the path, raise `NotFound`. If patterns match but none for this method, raise `MethodNotAllowed` with the methods of the matching patterns. A `HEAD` request is served by the `GET` handler when there is no `HEAD` handler, and `HEAD` counts in `allowed` wherever `GET` does.
- `dispatch(request) -> Response` resolves, stores the parameters in `request.params`, calls the handler and returns its response; for a `HEAD` served by a `GET` handler the body is replaced by `b''` and the headers are kept. It does not catch exceptions.

## `web/middleware.py`

A middleware is a function `mw(request, call_next) -> Response`, where `call_next(request)` runs the rest of the chain.

`App(router, middleware=())`, with `use(mw)` to append one:
- `handle(request) -> Response` runs the middleware in order, the first one outermost, with the router's `dispatch` innermost. The innermost step turns an `HTTPError` into an error response and any other exception into a 500 error response, so every middleware receives a `Response` from `call_next`. An exception raised by a middleware itself is converted the same way by `handle`.
- An error response has the error's status, the body `"<status> <reason>"` as text (via `Response.text`) and, for a `MethodNotAllowed`, an `Allow` header listing `allowed` joined with `", "`.
- `handle_bytes(data: bytes) -> bytes` parses the request, handles it and returns `to_bytes()` of the response. A `BadRequest` from parsing gives the 400 error response, without running any middleware.

Middleware factories in this module:
- `logger(lines: list)` appends `"<METHOD> <path> <status>"` to `lines` after each response.
- `cookies()` parses the `Cookie` header into `request.state['cookies']`, a dict (empty without the header). It splits the value on `;` and treats each piece exactly as a `Content-Type` parameter is treated (stripped, one pair of surrounding quotes removed, pieces without `=` skipped, first occurrence wins), except that cookie names keep their case.
- `basic_auth(users: dict[str, str], realm='app')` accepts a request whose `Authorization` header is `Basic ` followed by the Base64 of `user:password` (split at the first `:`) for a matching entry in `users`, and stores the user name in `request.state['user']`. Anything else gets a 401 error response with the header `WWW-Authenticate: Basic realm="<realm>"`, and the rest of the chain does not run.

`web/__init__.py` re-exports `Headers`, `Request`, `Response`, `parse_request`, `HTTPError`, `BadRequest`, `NotFound`, `MethodNotAllowed`, `Router`, `App`, `logger`, `cookies` and `basic_auth`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
