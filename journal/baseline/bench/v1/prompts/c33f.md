Extend the `todo/` package with priorities, due dates and sorting. Everything from the previous version keeps working exactly as before unless a rule below changes it, and files written by the previous version must still load.

## Model (`todo/model.py`)

- `Task` gains two fields after `done`: `priority: str = "normal"` and `due: datetime.date | None = None`.
- `normalize_priority(p: str) -> str` strips and lowercases; the result must be `"high"`, `"normal"` or `"low"`, or `ValueError` is raised.
- `parse_date(s: str) -> datetime.date` accepts only the form `YYYY-MM-DD` (four, two and two digits with hyphens, and a real calendar date). Anything else, such as `2026-1-5`, `20260105` or `2026-02-30`, raises `ValueError`.
- `Task.to_dict()` now returns the keys `id`, `title`, `tags`, `done`, `priority`, `due` in that order, with `due` as a `YYYY-MM-DD` string or `null`.
- `Task.from_dict(d)` treats `priority` and `due` as optional (defaults `"normal"` and `None`). When present they are validated with the rules above (`due` must be `null` or a valid date string), and `ValueError` is raised otherwise.

## Store (`todo/store.py`)

- The store now writes `"version": 2`. It reads files with version 1 (tasks without `priority` and `due`, which get the defaults) and version 2; any other version raises `StoreError`. A version 1 file is rewritten as version 2 the next time something changes, and never by just opening it.
- `add(title, tags=(), priority="normal", due=None) -> Task`, where `due` is a `datetime.date` or `None`.
- `edit(task_id, title=None, add_tags=(), remove_tags=(), priority=None, due=None, clear_due=False) -> Task`. `priority` and `due` change those fields when given; `clear_due=True` removes the due date. Giving both `due` and `clear_due=True` raises `ValueError`. As before, an invalid value changes nothing.
- `list(status="open", tags=(), overdue=False, today=None, sort="id") -> list[Task]`:
  - With `overdue=True` only open tasks whose due date is strictly before `today` are kept (a task due today is not overdue, and a done task never is). The status and tag filters still apply too. `overdue=True` without `today` raises `ValueError`.
  - `sort` is `"id"` (increasing id), `"priority"` (high, then normal, then low) or `"due"` (earliest due date first, tasks without a due date last). Ties are broken by increasing id. Any other `sort` raises `ValueError`.

## CLI (`todo/cli.py`)

- A new global option `--today YYYY-MM-DD`, given before the command like `--file`, sets the date used as today. It defaults to the system's current date.
- `add` takes `--priority high|normal|low` and `--due DATE`.
- `list` takes `--overdue` and `--sort id|priority|due` (default `id`).
- `edit` takes `--priority`, `--due DATE` and `--no-due`. Any one of `--title`, `--tag`, `--untag`, `--priority`, `--due` or `--no-due` is enough for an edit; `--due` together with `--no-due` is a usage error.
- A `list` line is now `<id> [ ] <title>`, then ` !high` or ` !low` when the priority is not normal, then ` due:YYYY-MM-DD` when the task has a due date, then the ` #tag` parts as before. For example `4 [ ] Pay rent !high due:2026-11-01 #home`. A normal-priority task with no due date prints exactly as before.
- An invalid date, in `--due` or `--today`, or an invalid priority is a usage error: exit code 2, nothing on stdout and nothing changed.

Use only the Python 3.12 standard library. Give the complete updated files, each in its own fenced code block, with the file's path on the line just before the block.
