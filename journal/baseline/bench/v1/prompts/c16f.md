Extend `toposort.py` with two functions. `toposort` and `CycleError` keep working exactly as before, and the new functions read `graph` the same way (a mapping from a node to the nodes it depends on; dependency-only nodes count as nodes; nothing is modified).

- `levels(graph) -> list[list[str]]` groups the nodes into layers that could be processed in parallel. A node with no dependencies is in level 0; any other node is in level `1 + ` the highest level among its dependencies, so its level is the length of its longest chain of dependencies. The result is the list of levels from 0 upwards, each level a list sorted by Python's `<`, with no empty levels. For example `levels({'app': ['lib', 'log'], 'lib': ['log'], 'cli': ['log']})` is `[['log'], ['cli', 'lib'], ['app']]`. An empty graph gives `[]`. If the graph has a cycle, raise `CycleError` exactly as `toposort` does.
- `subgraph_order(graph, targets) -> list[str]` returns only what is needed to build `targets`: the target nodes and every node they depend on, directly or indirectly, in the order `toposort` would give for the graph restricted to those nodes (same lexicographic tie-break). `targets` is any iterable of nodes and may repeat a node; no targets gives `[]`.
  - A target that is not a node of `graph` (neither a key nor a dependency) raises `KeyError`.
  - A cycle among the needed nodes raises `CycleError` as `toposort` does. A cycle elsewhere in the graph, among nodes the targets do not need, is ignored.
