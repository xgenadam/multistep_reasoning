Write a JSON parser and serializer from scratch in Python, as a package `js`. Do not use the standard `json` module anywhere in the package. The parser must report errors with a line and column, handle the number edge cases and `\u` surrogate pairs correctly, and `loads(dumps(x)) == x` must hold for every value `dumps` accepts (except that tuples come back as lists).

Layout:

```
js/__init__.py   re-exports loads, dumps, tokenize, Token, JSONError
js/scanner.py    JSONError, Token, tokenize(text)
js/parser.py     loads(text)
js/dump.py       dumps(obj, *, indent=None, sort_keys=False, ensure_ascii=False)
```

## Positions and errors

- `JSONError(msg, line, column)` is a subclass of `ValueError` with attributes `msg`, `line` and `column`; `str(e)` is `f"{msg} at line {line} column {column}"`. The message wording is up to you.
- Lines and columns are 1-based. Only `"\n"` starts a new line; the column is 1 plus the number of characters since the last `"\n"` (or since the start of the text). A `"\r"` is an ordinary whitespace character.
- Every error points at a character, as listed below. An error found at the end of the text points just past the last character (for `"[1,"` that is line 1, column 4; for empty text, line 1, column 1).

## Scanner (`js/scanner.py`)

`tokenize(text)` returns a list of `Token`s, the last of which has kind `'EOF'`. `Token` is a `NamedTuple` with fields `kind`, `value`, `line` and `column`, where `line` and `column` are the position of the token's first character (for `EOF`, the end-of-text position). Whitespace (space, tab, `"\n"`, `"\r"`) separates tokens and is otherwise ignored.

| Kind | Text | `value` |
| --- | --- | --- |
| `'{'` `'}'` `'['` `']'` `':'` `','` | that character | `None` |
| `'STRING'` | a string literal | the decoded `str` |
| `'NUMBER'` | a number | an `int`, or a `float` if the number has a fraction or an exponent |
| `'TRUE'` `'FALSE'` `'NULL'` | `true` `false` `null` | `True` `False` `None` |
| `'EOF'` | end of text | `None` |

- **Literals.** At an ASCII letter the scanner reads the whole run of ASCII letters. If the run is exactly `true`, `false` or `null` it is that token; otherwise it is an "invalid literal" error at the first letter (so `trueX` and `nul` are errors at their first character).
- **Numbers.** At `-` or a digit the scanner reads the whole run of characters from the set `0123456789+-.eE`. The run must be a complete JSON number: an optional `-`, then `0` or a digit 1–9 followed by digits, then optionally `.` and one or more digits, then optionally `e` or `E`, an optional sign and one or more digits. Otherwise the whole run is an "invalid number" error at its first character (so `01`, `-`, `1.`, `1e`, `1.5.2` and `1-2` are all errors at their first character). Integers are exact (`12345678901234567890` is an `int`); a float is Python's `float()` of the text (so `1e400` is `inf`). `-0` is the int `0`.
- **Strings.** Escapes are `\" \\ \/ \b \f \n \r \t` and `\uXXXX` with exactly four hex digits (either case). A `\u` escape of a high surrogate (D800–DBFF) must be followed immediately by a `\u` escape of a low surrogate (DC00–DFFF); the pair decodes to one character. Errors:
  - an unterminated string: at the opening quote;
  - an unknown escape, a `\u` without four hex digits, a high surrogate not followed by a low-surrogate escape, or a low surrogate on its own: at the backslash of the offending escape;
  - a raw control character (U+0000–U+001F) inside a string: at that character.
- Any other character (such as `+`, `.`, `'` or `#`) outside a string is an "unexpected character" error at that character.

## Parser (`js/parser.py`)

`loads(text)` returns the Python value: objects become `dict`s (a repeated key keeps its last value, in the position where the key first appeared), arrays become `list`s, and the scalars are the token values. Errors:

- a token that cannot appear where it is (a missing value, a trailing comma as in `[1,]` or `{"a":1,}`, a missing `:` or `,`, a non-string key): at that token;
- the text ending where a value or token is still needed: at the end-of-text position;
- anything but whitespace after the top-level value: at its first character;
- every scanner error, unchanged.

Errors are reported in reading order: the first problem in the text is the one raised.

## Serializer (`js/dump.py`)

`dumps(obj, *, indent=None, sort_keys=False, ensure_ascii=False)` returns a string.

- `None`, `True`, `False` become `null`, `true`, `false`. An `int` becomes its decimal digits. A finite `float` becomes `repr(f)`; `nan` and the infinities raise `ValueError`.
- Strings are quoted. `"` and `\` are escaped as `\"` and `\\`; `\b \f \n \r \t` use their short escapes; every other character below U+0020 becomes `\u00xx` (four lowercase hex digits). With `ensure_ascii=True`, every character above U+007F also becomes `\uxxxx`, and a character above U+FFFF becomes its UTF-16 surrogate pair (`"😀"` → `"😀"`). Without it, those characters are written as they are.
- `list` and `tuple` become arrays; `dict` becomes an object. A dict key that is not a `str` raises `TypeError`, as does any value of another type.
- A container that contains itself, directly or through other containers, raises `ValueError`. The same container appearing twice without a cycle (`[x, x]`) is fine.
- With `indent=None` the output is compact, with no spaces at all: `{"a":[1,2]}`.
- With `indent=n` (an int ≥ 0; a negative one raises `ValueError`), each array element and object member goes on its own line, indented by `n` spaces per nesting level; elements are followed by `,` except the last; an object member is written `"key": value` (one space after the colon). An empty list or dict is written `[]` or `{}`. So `dumps({"a": [1, 2], "b": {}}, indent=2)` is:

  ```
  {
    "a": [
      1,
      2
    ],
    "b": {}
  }
  ```

- With `sort_keys=True` object members are written in ascending order of their keys; otherwise in dict order.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
