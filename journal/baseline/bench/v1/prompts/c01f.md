Extend `wordcount.py` with standard input and JSON output. Without the new options everything works exactly as before: same table, same counting rules, same error messages and exit statuses.

- A FILE given as `-` means standard input. Read it as UTF-8 bytes with no newline translation, exactly like a file, so `\r\n` still counts as two characters. In the table its `file` cell is `-`, and it counts as a readable file for the total row.
- A new option `--json` may appear anywhere among the arguments. With it, standard output is a single JSON object instead of the table:

  ```
  {"files": [{"file": "a.txt", "lines": 3, "words": 12, "chars": 61}, ...],
   "total": {"lines": 3, "words": 12, "chars": 61}}
  ```

  `files` lists the readable files in command-line order, each with the path as given (`-` for standard input) and its three counts as integers. `total` sums them and is always present, even for a single file. Any whitespace or indentation in the JSON is fine.
- With `--json`, unreadable files are still reported on standard error with the same `wordcount.py: cannot read FILE` line and left out, and the exit status is still 1 if any FILE could not be read. The JSON object is printed even when no FILE was readable (then `files` is empty and every total is 0).
- At least one FILE is still required, with or without `--json`; with none, it remains a usage error with exit status 2.

Use only the Python 3.12 standard library. Give the complete updated files, each in its own fenced code block, with the file's path on the line just before the block.
