Extend `minisql` with qualified column names, an inner join, aggregates and `GROUP BY`. Every query the previous version accepted keeps giving exactly the same result, and every error it raised stays the same type, except that `JOIN ON GROUP AS COUNT SUM AVG MIN MAX` are now keywords and can no longer be used as names.

## Grammar

```
SELECT select_list FROM table [JOIN table ON ref = ref] [WHERE condition]
       [GROUP BY ref {, ref}] [ORDER BY order_item {, order_item}] [LIMIT n]
select_list := * | item {, item}
item        := (ref | aggregate) [AS name]
aggregate   := COUNT ( * ) | func ( ref )        func := COUNT | SUM | AVG | MIN | MAX
order_item  := (ref | aggregate) [ASC | DESC]
ref         := name | table . name
```

`condition` and `operand` are as before, except that an operand name may now be a `ref`. Aggregates are not allowed in a condition.

## Tokens

- The new keywords above are matched case-insensitively like the old ones.
- A `.` that is not part of a number is a token of kind `DOT` with the value `'.'`. A number is still digits with an optional `.` followed by digits, so `1.` is still an error at the `.`.

## Syntax tree

- `Column(name)` holds the reference's canonical text: `name` or `table.name`, with no spaces even if the query has some (`p . id` is `p.id`).
- New: `@dataclass(frozen=True) class Aggregate(func: str, arg)`, with `func` in upper case and `arg` a `Column`, or `None` for `COUNT(*)`. Its canonical text is `FUNC(arg)` with no spaces, for example `COUNT(*)` or `SUM(o.amount)`.
- New: `@dataclass(frozen=True) class Join(table: str, left: Column, right: Column)` for `JOIN table ON left = right`.
- `Select` keeps its five fields and gains three more, in this order and with these defaults: `items: list = []`, `join = None`, `group_by: list = []`.
  - `items` is a list of `(expr, key)` tuples, one per select item, where `expr` is a `Column` or an `Aggregate` and `key` is the item's output key: its alias if it has one, else its canonical text. It is empty for `*`.
  - `columns` is `None` for `*`, else the list of output keys in order.
  - `join` is a `Join` or `None`. `group_by` is the list of the `GROUP BY` references' canonical texts.
  - Each `order_by` entry is `(text, descending)`, where `text` is the canonical text of the ref or aggregate written there.
- `minisql/__init__.py` also exports `Aggregate` and `Join`.

## Syntax errors (`SQLSyntaxError`, raised by `parse`)

Besides any token that does not fit the grammar:

- Two select items with the same output key. The position is the first token of the second one.
- `*` in a grouped query, at the `*`. A query is *grouped* when it has `GROUP BY` or any aggregate in its select list.
- In a grouped query, a select item that is a plain ref but is not one of the `GROUP BY` refs (same canonical text). The position is that item's first token.
- An aggregate in `ORDER BY` of a query that is not grouped, at the aggregate's first token.

## Execution

1. **Names.** Without `JOIN`, `name` and `table.name` both read the column `name` of the row, where `table` must be the `FROM` table; any other qualifier raises `SQLExecutionError`. With `JOIN`, every reference anywhere in the query must be qualified with one of the two tables; an unqualified reference, or a qualifier that is neither table, raises `SQLExecutionError`. The one exception is an `ORDER BY` name equal to a select alias (rule 6).
2. **Join.** `FROM a JOIN b ON p = q` requires `a` and `b` to be different tables (`SQLExecutionError` otherwise; unknown tables are `SQLExecutionError` as before). One of `p` and `q` must name a column of `a` and the other a column of `b`, in either order; otherwise `SQLExecutionError`. The joined rows are, for each row of `a` in order and then each row of `b` in order, the pairs where the two values compare equal by the `=` rule (so `NULL` never matches and values of different kinds never match). A joined row is a dict with the keys `a.k` for each key of the `a` row, in its order, followed by `b.k` for each key of the `b` row. `SELECT *` returns copies of these dicts.
3. **Then** `WHERE` filters, then grouping, then `ORDER BY`, then `LIMIT`.
4. **Groups.** In a grouped query the kept rows are split into groups that share their `GROUP BY` values: two values belong together when both are `NULL`, or when they are of the same kind and equal. Groups come out in the order of their first row. Each group gives one output row. Without `GROUP BY`, all kept rows form one group, and the query returns exactly one row even when no row is kept. With `GROUP BY` and no kept rows it returns `[]`.
5. **Aggregates** look only at the group's rows and skip `NULL`s:
   - `COUNT(*)` counts rows; `COUNT(ref)` counts non-`NULL` values.
   - `SUM` adds the values. The result is an `int` when every value is an `int`, else a `float`. It is `NULL` when there are no values.
   - `AVG` is the sum divided by the count, always a `float`, or `NULL` when there are no values.
   - `MIN` and `MAX` give the smallest and largest value by the comparison rules (strings and booleans allowed), or `NULL` when there are no values.
   - `SUM` or `AVG` over a non-`NULL` value that is not a number, or `MIN` or `MAX` over values of different kinds, raises `SQLExecutionError`.
6. **Ordering.** In a grouped query, each `ORDER BY` text must equal the alias or the canonical text of a select item, and sorts the output rows by that item's value. Anything else raises `SQLExecutionError`. In a query that is not grouped, a name equal to a select alias sorts by that item's value, and any other ref sorts by that column of the row as before. Stability, `NULL` placement and the mixed-kind error are as before.
7. **Output keys.** Each result row has the output keys of the select items, in order: the alias, else the canonical text (`SELECT p.name, COUNT(*) AS n` gives keys `p.name` and `n`).
