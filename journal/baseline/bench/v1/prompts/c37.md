Write a small Markdown-to-HTML converter as a Python package `md2html`. It implements the subset of Markdown below, with exact output rules (this is not CommonMark; where they differ, follow these rules).

## Files and public API

- `md2html/blocks.py`: `parse_blocks(text: str) -> list[tuple]` splits a document into blocks (shapes below).
- `md2html/inline.py`: `render_inline(text: str) -> str` renders inline markup to HTML, and `escape_html(text: str) -> str` replaces `&`, `<`, `>` and `"` with `&amp;`, `&lt;`, `&gt;` and `&quot;` (in that order of priority, so `&` is never escaped twice; `'` is left alone).
- `md2html/render.py`: `render_blocks(blocks: list[tuple]) -> str` and `to_html(text: str) -> str`, which is `render_blocks(parse_blocks(text))` followed by one `"\n"`, or `""` when the document has no blocks.
- `md2html/__init__.py` exports `to_html`, `parse_blocks`, `render_blocks`, `render_inline` and `escape_html`.

## Blocks

The input is split into lines on `\n` (`\r\n` and `\r` count as `\n`). A blank line is one that is empty or contains only whitespace. Every block marker is recognised only at the very start of a line: a line that begins with a space is never a block start; it is paragraph text, or a continuation line of a list item.

The parser reads the lines in order. Blank lines between blocks are skipped. At each non-blank line, the first of these rules that matches decides what starts there:

1. **Fenced code.** A line starting with three or more backticks opens a code block. The rest of the line, split on whitespace, gives the language: its first word, or `""` if there is none. The block holds every following line verbatim until a closing fence: a line consisting only of backticks (trailing whitespace allowed), at least as many as the opening fence. A fence that is never closed runs to the end of the document. Shape: `("code", lang, code)`, where `code` is each content line followed by `"\n"`, concatenated (`""` for no lines).
2. **Heading.** One to six `#` characters followed by a space or by the end of the line. The text is the rest of the line stripped of whitespace; then a final run of `#` characters is removed if it is the whole text or is preceded by whitespace, and the result is stripped again (`## Title ##` gives `Title`; `# C#` keeps `C#`). `#tag` and `####### x` are not headings. Shape: `("heading", level, text)`.
3. **Horizontal rule.** A line made of three or more of the same character, `-`, `*` or `_`, optionally with spaces between and after them, and nothing else (`---`, `* * *`, `_ _ _ _`). Shape: `("hr",)`.
4. **Blockquote.** A line starting with `>`. The blockquote is that line and every directly following line that starts with `>`; it ends at the first line that does not (a blank line included). From each line remove the `>` and then one space if one follows it. The resulting lines are parsed as a document of their own. Shape: `("blockquote", children)` with `children` a list of blocks.
5. **List.** A bullet item is `-`, `*` or `+` followed by a space; an ordered item is 1 to 9 digits, a `.` and a space. The item's text is the rest of the line, stripped. A list is a run of items of the same kind: the same bullet character, or ordered. Items need not be numbered in sequence. The list continues line by line:
   - an item of the same kind adds a new item;
   - an item of a different kind, a blank line or a line that starts any other block (rules 1–4) ends the list (a line like `- - -` is a horizontal rule, so it ends the list);
   - any other line is a continuation of the last item: it is stripped and appended to the item's text after a `"\n"`.
   Shape: `("list", ordered, start, items)`, where `ordered` is a bool, `start` is the first item's number as an `int` for an ordered list (`"007."` gives 7) and `None` for a bullet list, and `items` is a list of the items' texts.
6. **Paragraph.** Otherwise a paragraph starts. It runs over the following lines until a blank line or a line that starts a block by rules 1–5 (so a list item, heading, rule, fence or `>` line interrupts a paragraph). Each line is stripped and the lines are joined with `"\n"`. Shape: `("paragraph", text)`.

## HTML output

`render_blocks` renders each block and joins them with `"\n"`:

- heading: `<hN>inline</hN>`;
- paragraph: `<p>inline</p>` (the `"\n"` between the paragraph's lines stays in the output);
- code: `<pre><code class="language-LANG">CODE</code></pre>`, with `CODE` and `LANG` passed through `escape_html` and no inline processing; without a language: `<pre><code>CODE</code></pre>`;
- blockquote: `<blockquote>`, a newline, the children rendered by `render_blocks`, a newline and `</blockquote>`; an empty blockquote is `<blockquote>\n</blockquote>`;
- list: `<ul>` or `<ol>`, a newline, one `<li>inline</li>` per item joined by newlines, a newline and `</ul>` or `</ol>`. An ordered list whose start is not 1 opens with `<ol start="N">`;
- rule: `<hr />`.

Here "inline" means the text passed through `render_inline`.

## Inline markup

`render_inline` scans the text from left to right. At each position the first matching rule applies; text that matches no rule is output with `escape_html`.

1. **Backslash escape.** A `\` followed by an ASCII punctuation character (`string.punctuation`) outputs that character literally (HTML-escaped) and gives it no special meaning. Any other `\` is a literal backslash.
2. **Code span.** A run of N backticks opens a code span that closes at the next run of exactly N backticks. The content between them is output inside `<code>...</code>` with `escape_html` and no other processing (backslashes are literal there). If the content begins and ends with a space and is not only spaces, one space is removed from each end. If no closing run exists, the opening run is output as literal backticks.
3. **Image.** `![alt](url)` or `![alt](url "title")` outputs `<img src="URL" alt="ALT" />`, or `<img src="URL" alt="ALT" title="TITLE" />` with a title.
4. **Link.** `[label](url)` or `[label](url "title")` outputs `<a href="URL">LABEL</a>` or `<a href="URL" title="TITLE">LABEL</a>`.
5. **Emphasis.** `**text**` or `__text__` outputs `<strong>text</strong>`; `*text*` or `_text_` outputs `<em>text</em>`.
6. Anything else is a single character, output with `escape_html`.

Link and image details: the label (or alt) is everything up to the first `]`, which must be followed directly by `(`. The URL is everything after `(` up to the first space or `)`; it may be empty. A title is optional: one or more spaces, then a double-quoted string without `"` inside, then optional spaces. The destination must end with `)`. If any of this fails, the `[` (or `!`) is an ordinary character and scanning continues after it. The label of a link is rendered with `render_inline`; an image's alt text, the URL and the title get `escape_html` only.

Emphasis details:
- At a `*` or `_`, first try the double delimiter (`**` or `__`) if the text has two, then the single one.
- An opening delimiter must be followed by a character that is not whitespace. A `_` opener must not be preceded by a letter or digit (so `snake_case_name` stays as it is).
- The closer is the first later occurrence of the same delimiter, at least one character after the opener's end, that is preceded by a non-whitespace character and is not escaped with a backslash (the search skips each `\` and the character after it). A single `*` or `_` closer must not have the same character directly before or after it. A `_` or `__` closer must not be followed by a letter or digit.
- The text between opener and closer is rendered with `render_inline`, so emphasis nests: `**bold *both* bold**` gives `<strong>bold <em>both</em> bold</strong>`.
- When no closer is found, the delimiter character is output as itself and scanning continues with the next character.

For example, `to_html("# Hi *there*\n\nSome `code` & [a link](http://x.org/?a=1&b=2).\n\n- one\n- two\n")` returns:

```
<h1>Hi <em>there</em></h1>
<p>Some <code>code</code> &amp; <a href="http://x.org/?a=1&amp;b=2">a link</a>.</p>
<ul>
<li>one</li>
<li>two</li>
</ul>
```

(with a final newline after `</ul>`).

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
