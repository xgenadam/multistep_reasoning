Write a small Python package `cal` for scheduling meetings: one-off events, weekly recurring series with skipped dates, conflict detection, and finding common free time for a group of people.

All times are naive `datetime.datetime` values in one local time zone. Every event occupies the half-open interval `[start, end)`. Two intervals overlap when each one starts before the other ends, so an event ending at 10:00 does not overlap one starting at 10:00. Conflict detection and free-slot search must both use this same rule.

Layout:

```
cal/__init__.py      re-exports Event, Calendar, Recurring, overlaps, merge, busy_intervals,
                     find_conflicts, free_slots, first_free
cal/events.py        Event, Calendar
cal/recurrence.py    Recurring
cal/slots.py         overlaps, merge, busy_intervals, find_conflicts, free_slots, first_free
```

`cal/events.py`

- `Event(title, start, end, attendees=())` is a frozen dataclass with the fields `title: str`, `start: datetime`, `end: datetime` and `attendees: frozenset[str]`. The constructor accepts any iterable of names for `attendees` and stores it as a `frozenset`. It raises `ValueError` if `end <= start`. Events compare equal when all four fields are equal.
- `Calendar()` holds one-off events and recurring series.
  - `add(item)` adds an `Event` or a `Recurring`; anything else raises `TypeError`.
  - `events_between(start, end)` returns a list of every event (one-off events and the expanded occurrences of every series) that overlaps `[start, end)`, sorted by `(start, end, title)`.
  - `events_for(person, start, end)` is the same list restricted to events whose attendees include `person`.

`cal/recurrence.py`

`Recurring(title, start, end, attendees=(), *, weekdays=None, interval=1, until=None, count=None, exceptions=(), moves=None)` describes a weekly series. `start` and `end` are the first possible occurrence; every occurrence has the same time of day and the same duration.

- `weekdays` is an iterable of integers, Monday = 0 to Sunday = 6; `None` means `start`'s weekday only.
- The series is built week by week. Week 0 is the Monday-to-Sunday week that contains `start`, and only weeks 0, `interval`, 2 × `interval`, … are used. Within a used week, there is a candidate occurrence on each listed weekday, in date order. A candidate earlier than `start` is not part of the series. (So if `start`'s own weekday is not listed, `start` itself is not an occurrence.)
- `until` is a `datetime.date`: candidates on a later date are not part of the series (the `until` date itself is included).
- `count` limits the series to its first `count` candidates.
- `exceptions` is an iterable of `datetime.date`s. A candidate on one of those dates is skipped, but it still uses up one of the `count` candidates.
- `moves` is a dict mapping a candidate's date to a new `(start, end)` pair of datetimes: that one occurrence takes place at the new times instead (the new times may be on any date, even one outside the window the candidate falls in). A moved occurrence still uses up its `count` candidate. A key that is not the date of a candidate has no effect.
- With neither `until` nor `count` the series never ends.
- The constructor raises `ValueError` if `end <= start`, if `weekdays` is empty or holds a value outside 0–6, if `interval < 1`, if `count` is given and is less than 1, if a move's end is not after its start, or if a date is both an exception and a move key.
- `occurrences(window_start, window_end)` returns a list of `Event`s (with the series' title and attendees) for the occurrences, after skips and moves, that overlap `[window_start, window_end)`, sorted by `(start, end)`. It must terminate for a series that never ends.

`cal/slots.py`

An interval here is a `(start, end)` tuple of datetimes with `start < end`.

- `overlaps(a, b)` returns whether intervals `a` and `b` overlap, by the rule above.
- `merge(intervals)` returns a new list of intervals sorted by start, where intervals that overlap or touch (one ends exactly where the next starts) are joined into one.
- `busy_intervals(calendar, people, start, end)` returns `merge` of the intervals of every event in `calendar.events_between(start, end)` that has at least one of `people` as an attendee, each clipped to `[start, end)`.
- `find_conflicts(calendar, start, end)` looks at `calendar.events_between(start, end)` and returns every pair of those events that overlap in time and share at least one attendee. Each pair is a tuple `(a, b)` where `a` comes before `b` in `events_between` order, and the list is sorted by the positions of `a` and then `b` in that order.
- `free_slots(calendar, people, start, end, *, min_length=timedelta(0), day_start=None, day_end=None)` returns the intervals inside `[start, end)` when none of `people` is busy. A person is busy during every event in which they are an attendee; other events do not matter. If `day_start` and `day_end` (`datetime.time` values) are given, free time is further limited to `[day_start, day_end)` on each calendar day, so a free stretch that crosses a day boundary is reported as separate per-day slots. The result is sorted by start, holds only slots of positive length that are at least `min_length` long, and never contains two slots that touch or overlap. It raises `ValueError` if `people` is empty, if only one of `day_start`/`day_end` is given, or if `day_end <= day_start`.
- `first_free(calendar, people, start, end, duration, *, day_start=None, day_end=None)` returns the earliest interval `(s, s + duration)` that lies entirely inside one of the slots `free_slots` would return for the same arguments, or `None` if no slot is long enough. It raises `ValueError` if `duration` is not positive, and otherwise for the same reasons as `free_slots`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
