Write a small stock-keeping library as a Python package `inventory/` with five files: `inventory/__init__.py`, `inventory/models.py`, `inventory/movements.py`, `inventory/valuation.py` and `inventory/reports.py`. It records stock movements for items held in several locations, values the stock by FIFO or by moving average cost, and prints two CSV reports.

Quantities are positive `int`s (a `bool` is not accepted). Money is `decimal.Decimal`. Days are `datetime.date`. SKUs, item names, categories and location names are non-empty strings that never contain a comma.

## `inventory/models.py`

- `InventoryError(Exception)`, and two subclasses: `UnknownItemError(InventoryError)` for a SKU that was never added, and `InsufficientStockError(InventoryError)` for taking more stock out of a location than it holds.
- `Item(sku: str, name: str, category: str)`: a frozen dataclass.
- `Movement`: a frozen dataclass with fields `seq: int`, `day: datetime.date`, `kind: str`, `sku: str`, `qty: int`, `location: str`, `to_location: str | None` and `unit_cost: Decimal | None`. `kind` is `"receive"`, `"issue"` or `"transfer"`. `seq` numbers the movements 1, 2, 3, ... in the order they were recorded. `to_location` is set only for a transfer and `unit_cost` only for a receipt.

## `inventory/movements.py`

`Ledger()` holds the items and the movements.

- `add_item(item: Item) -> None`; adding a SKU that already exists raises `ValueError`.
- `item(sku) -> Item` (`UnknownItemError` if missing) and `items() -> list[Item]` sorted by SKU.
- `receive(day, sku, location, qty, unit_cost) -> Movement` brings stock into a location at a unit cost. `unit_cost` may be a `Decimal`, an `int` or a numeric `str` and is stored as a `Decimal`; a `float` raises `TypeError` and a negative cost raises `ValueError`.
- `issue(day, sku, location, qty) -> Movement` takes stock out of a location (a sale or use).
- `transfer(day, sku, from_location, to_location, qty) -> Movement` moves stock between locations; the two locations must differ (`ValueError`).
- Every recording method checks, in this order, and raises without recording anything:
  1. `UnknownItemError` for an unknown SKU;
  2. `ValueError` for a quantity that is not a positive int;
  3. `ValueError` if `day` is earlier than the day of the last recorded movement (the same day is fine);
  4. `InsufficientStockError` if an issue or transfer needs more than the location holds.
- `movements(sku=None, as_of=None) -> list[Movement]`: the movements in recording order, optionally only one SKU's, and only those with `day <= as_of` when `as_of` is given.
- `on_hand(sku, location=None, as_of=None) -> int`: the quantity held, in one location or (with `location=None`) in all of them together, counting only movements with `day <= as_of` when given. `UnknownItemError` for an unknown SKU.
- `locations() -> list[str]`: every location used by any movement, sorted.

## `inventory/valuation.py`

Valuation is per SKU across all locations together: where the stock sits does not matter, and a transfer changes no cost.

- `Valuation`: a frozen dataclass `(qty: int, value: Decimal, cogs: Decimal)`: the quantity on hand, the value of that stock, and the cost of goods issued so far. `value` and `cogs` are rounded to cents (`Decimal("0.01")`, `ROUND_HALF_UP`).
- `fifo(ledger, sku, as_of=None) -> Valuation`. Each receipt adds a cost layer. An issue consumes the oldest layers first, possibly across several layers. `value` is the sum of quantity × unit cost over what is left of the layers; `cogs` is the sum of quantity × unit cost over everything issued. Both are computed exactly and rounded once at the end.
- `average(ledger, sku, as_of=None) -> Valuation`, moving weighted average. Keep a running quantity and value. A receipt adds its quantity and quantity × unit cost. An issue's cost is the running value × issued quantity / running quantity, rounded to cents, except that issuing all of the remaining quantity costs exactly the remaining value. The cost is subtracted from the running value and added to `cogs`.
- `valuate(ledger, sku, method="fifo", as_of=None) -> Valuation` calls one of the two; any `method` other than `"fifo"` or `"average"` raises `ValueError`.
- All three raise `UnknownItemError` for an unknown SKU, and count only movements with `day <= as_of` when `as_of` is given.

## `inventory/reports.py`

Two reports. Each returns a string of CSV lines with no quoting, each line ending in `\n`. Both use the same layout:

- a header line;
- the groups in sorted order. Each group has one line per SKU, sorted by SKU, followed by a subtotal line whose SKU column is `TOTAL`;
- a SKU whose quantity is 0 is left out, and a group with no lines left is left out entirely;
- a last grand-total line whose first column is `TOTAL` and whose SKU column is empty. It is always present, even when nothing else is.

`stock_report(ledger, as_of=None, location=None) -> str`: stock on hand grouped by location. The header is `location,sku,qty`; a line is `<location>,<sku>,<qty>`. With `location` given, only that location's group is shown and the grand total covers only it. For example:

```
location,sku,qty
east,B-1,4
east,W-2,10
east,TOTAL,14
west,B-1,3
west,TOTAL,3
TOTAL,,17
```

`valuation_report(ledger, as_of=None, method="fifo", category=None) -> str`: stock on hand across all locations and its value, grouped by item category. The header is `category,sku,qty,value`; a line is `<category>,<sku>,<qty>,<value>` with the value from `valuate` printed with exactly two decimals. Subtotal and grand-total values are sums of the lines' values. With `category` given, only that category is shown. An invalid `method` raises `ValueError`. For example:

```
category,sku,qty,value
bolts,B-1,7,17.50
bolts,TOTAL,7,17.50
widgets,W-2,10,55.00
widgets,TOTAL,10,55.00
TOTAL,,17,72.50
```

`inventory/__init__.py` exports `Item`, `Movement`, `Ledger`, `Valuation`, `InventoryError`, `UnknownItemError`, `InsufficientStockError`, `fifo`, `average`, `valuate`, `stock_report` and `valuation_report`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
