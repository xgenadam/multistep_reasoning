Write a small content-addressed object store in the style of git, in Python, as a package `objstore`: blobs, trees and commits identified by the SHA-1 of a fixed serialisation, an in-memory store, history walking and a tree diff.

Layout:

```
objstore/__init__.py   re-exports Blob, Tree, TreeEntry, Commit, serialize, object_id,
                       parse_object, CorruptObject, ObjectStore, ObjectNotFound,
                       AmbiguousPrefix, Change, diff_trees, diff_commits, format_changes
objstore/objects.py    Blob, TreeEntry, Tree, Commit, serialize, object_id, parse_object, CorruptObject
objstore/store.py      ObjectStore, ObjectNotFound, AmbiguousPrefix
objstore/diff.py       Change, diff_trees, diff_commits, format_changes
```

An *oid* is the 40-character lowercase hex SHA-1 of an object's serialisation.

## Objects (`objstore/objects.py`)

All three are frozen dataclasses, compared by value.

- `Blob(data: bytes)`.
- `TreeEntry(name: str, kind: str, oid: str)`, a `NamedTuple`; `kind` is `'blob'` or `'tree'`. A name must be non-empty, must not be `.` or `..`, and must not contain `/`, `"\0"`, `"\t"` or `"\n"`.
- `Tree(entries)` takes any iterable of `TreeEntry`s and stores them in its field `entries` as a tuple sorted by the UTF-8 bytes of the names. A repeated name, a bad name, a bad kind or a bad oid raises `ValueError`.
- `Commit(tree: str, parents: tuple[str, ...], author: str, timestamp: int, message: str)`. `tree` and each parent must be valid oids, `author` must not contain `"\n"`, and `timestamp` must be an int ≥ 0; otherwise `ValueError`. `parents` may be given as any iterable and is stored as a tuple, in the given order.

Serialisation, `serialize(obj) -> bytes`, is a header followed by a body: the header is the ASCII text `TYPE LENGTH` followed by one zero byte, where `TYPE` is `blob`, `tree` or `commit` and `LENGTH` is the body's length in bytes, in decimal. Bodies:

- blob: the data itself (so blob oids are the same as git's);
- tree: for each entry in order, the UTF-8 encoding of `f"{kind} {oid}\t{name}\n"` (an empty tree has an empty body);
- commit: the UTF-8 encoding of `f"tree {tree}\n"`, then `f"parent {p}\n"` for each parent in order, then `f"author {author}\n"`, `f"time {timestamp}\n"`, a blank line `"\n"`, and the message exactly as given.

`object_id(obj)` returns the oid. `parse_object(raw)` turns a serialisation back into the equal object; it raises `CorruptObject` (a subclass of `ValueError`) if the header is malformed, the length does not match, the type is unknown, or the body does not follow the format above (including invalid values).

## Store (`objstore/store.py`)

`ObjectStore()` keeps serialised objects in memory, keyed by oid.

- `put(obj)` stores the object and returns its oid; storing the same object twice is harmless. `put_raw(raw)` stores a serialisation after checking it with `parse_object`, and returns its oid.
- `get(oid)` returns the object, and `get_raw(oid)` its serialisation; both raise `ObjectNotFound` (a subclass of `KeyError`) for an unknown oid. `oid in store` tells whether it is stored.
- `resolve(prefix)` returns the one stored oid that starts with `prefix`. The prefix must be 4 to 40 lowercase hex characters (`ValueError` otherwise). No match raises `ObjectNotFound`; more than one raises `AmbiguousPrefix` (a subclass of `ValueError`).
- `write_tree(files)` takes a dict from slash-separated paths (`'src/app.py'`) to bytes, stores a blob for every file and a tree for every directory, and returns the root tree's oid. A path with an empty part, a leading or trailing `/`, or a bad name, and a path that is both a file and a directory (`'a'` and `'a/b'`), raise `ValueError`. An empty dict gives the empty tree.
- `read_tree(oid)` returns the dict from every file's full path to its bytes, with keys sorted.
- `commit(tree, parents=(), *, author, timestamp, message)` stores a `Commit` and returns its oid. It raises `ObjectNotFound` if the tree or a parent is not stored, and `ValueError` if the tree is not a tree or a parent is not a commit.
- `log(oid, first_parent=False)` returns commit oids. By default: the commit and all its ancestors, each exactly once, ordered by timestamp, newest first, with equal timestamps ordered by oid ascending. With `first_parent=True`: the commit, its first parent, that commit's first parent, and so on until a root commit.

## Diff (`objstore/diff.py`)

- `Change` is a `NamedTuple` with fields `status` (`'A'` added, `'D'` deleted, `'M'` modified), `path`, `old` and `new` (blob oids, `None` on the side where the file does not exist).
- `diff_trees(store, old, new)` compares two trees given by oid (`None` stands for an empty tree) and returns one `Change` per file path that differs, sorted by path. A file present in both with a different blob is `'M'`. Where a name is a file on one side and a directory on the other, the file is deleted or added and every file under the directory is added or deleted. Subtrees with the same oid on both sides are equal and must be skipped without being read.
- `diff_commits(store, old, new)` diffs the trees of two commits; `old` may be `None` (everything in `new` is added).
- `format_changes(changes)` returns one line per change, `f"{status}\t{path}\n"`, concatenated.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
