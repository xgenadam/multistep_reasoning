Write a small command-line todo manager as a Python package `todo/` with four files: `todo/__init__.py`, `todo/model.py`, `todo/store.py` and `todo/cli.py`. Tasks live in one JSON file. It is run as `python -m todo.cli ...`.

## `todo/model.py`

- `normalize_title(title: str) -> str` strips surrounding whitespace and returns the result. It raises `ValueError` if nothing is left.
- `normalize_tag(tag: str) -> str` strips surrounding whitespace and lowercases. The result must match `[a-z0-9][a-z0-9_-]*` in full, or `ValueError` is raised. So `" Work "` becomes `"work"`, and `""`, `"-x"` and `"a b"` are rejected.
- `Task` is a dataclass with fields `id: int`, `title: str`, `tags: list[str]` and `done: bool = False`. `tags` is always sorted, without duplicates, and every tag is normalized.
- `Task.to_dict()` returns `{"id": ..., "title": ..., "tags": [...], "done": ...}` with the keys in that order.
- `Task.from_dict(d)` builds a task from such a dict. It raises `ValueError` if a key is missing, a value has the wrong type (`id` an int but not a bool, `title` a str, `tags` a list of str, `done` a bool), or the title or a tag is invalid. It normalizes the title and tags the same way the store does.

## `todo/store.py`

- `StoreError(Exception)`: the file cannot be read as a todo file.
- `TodoStore(path)` opens the store at `path` (a `str` or `pathlib.Path`). A missing file is an empty store, and opening one never creates the file. A file that is not valid JSON, or does not have the shape below, raises `StoreError` from the constructor.
- The file is a JSON object `{"version": 1, "next_id": N, "tasks": [...]}`, where each task is `Task.to_dict()` and the tasks are in increasing id order. Any task with an id not below `next_id`, or two tasks with the same id, make the file invalid.
- Ids are stable: the first task gets id 1 and each new task gets `next_id`, which then goes up by one. An id is never reused, even after the task with the highest id is removed.
- Every method that changes something writes the whole file before returning (write a temporary file next to it, then replace). Methods that only read never write.
- Methods:
  - `add(title: str, tags=()) -> Task` adds an open task and returns it. Tags are normalized, deduplicated and sorted.
  - `get(task_id: int) -> Task` returns the task or raises `KeyError`.
  - `list(status: str = "open", tags=()) -> list[Task]` returns the tasks in increasing id order. `status` is `"open"`, `"done"` or `"all"` (`ValueError` otherwise). With `tags`, a task is listed only if it has every one of them (they are normalized first).
  - `mark_done(task_id: int) -> Task` marks the task done and returns it. Marking a done task again is allowed and changes nothing. `KeyError` if the id is missing.
  - `remove(task_id: int) -> Task` deletes the task and returns it, or raises `KeyError`.
  - `edit(task_id: int, title: str | None = None, add_tags=(), remove_tags=()) -> Task` changes the title if one is given, adds `add_tags`, then removes `remove_tags` (removing a tag the task does not have is not an error). `KeyError` if the id is missing; `ValueError` for an invalid title or tag, and then nothing changes.
- The store never hands out its own objects: changing a returned `Task` does not change the store.

## `todo/cli.py`

`main(argv: list[str] | None = None) -> int` runs one command and returns the exit code, and `python -m todo.cli` calls `sys.exit(main())`. Use `argparse`. A global option `--file PATH`, given before the command, names the store file; it defaults to `todo.json` in the current directory.

| Command | Effect | Prints on success |
| --- | --- | --- |
| `add TITLE [--tag TAG]...` | adds a task | `added <id>` |
| `list [--status open\|done\|all] [--tag TAG]...` | lists tasks (status defaults to `open`; repeated `--tag` means all of them) | one line per task |
| `done ID [ID...]` | marks each task done | `done <id>` for each, in the order given |
| `remove ID` | removes the task | `removed <id>` |
| `edit ID [--title TITLE] [--tag TAG]... [--untag TAG]...` | edits the task | `edited <id>` |

- A task's `list` line is `<id> [ ] <title>` for an open task and `<id> [x] <title>` for a done one, followed by ` #tag` for each tag in sorted order. For example `3 [x] Buy milk #home #shop`. `list` prints nothing when no task matches.
- `done` checks every id before changing anything: if any id does not exist, no task is marked.
- Exit codes and errors. On any error nothing goes to stdout. Apart from argparse's own messages, an error is one line on stderr that starts with `error: `.
  - 0: success.
  - 1: a task id does not exist (`error: no task with id <id>`, naming the first missing id).
  - 2: a usage error: argparse's own errors, an invalid title or tag, or `edit` with none of `--title`, `--tag` and `--untag`.
  - 3: the store file is invalid (`error: ` followed by the reason).
- `__init__.py` exports `Task`, `TodoStore` and `StoreError`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
