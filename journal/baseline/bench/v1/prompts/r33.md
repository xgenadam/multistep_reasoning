Write the data dictionary entry for the `subscriptions` table in Billwise's billing database. Its readers are analysts writing reports and engineers new to the team. Here is the DDL:

```sql
CREATE TABLE subscriptions (
  subscription_id    BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  account_id         BIGINT NOT NULL REFERENCES accounts (account_id),
  plan_code          VARCHAR(20) NOT NULL REFERENCES plans (plan_code),
  status             VARCHAR(12) NOT NULL
                     CHECK (status IN ('trialing', 'active', 'past_due', 'cancelled')),
  seats              INTEGER NOT NULL DEFAULT 1 CHECK (seats BETWEEN 1 AND 500),
  billing_interval   CHAR(1) NOT NULL CHECK (billing_interval IN ('M', 'Y')),
  unit_price_cents   INTEGER NOT NULL CHECK (unit_price_cents >= 0),
  currency           CHAR(3) NOT NULL DEFAULT 'EUR',
  trial_ends_at      TIMESTAMPTZ,
  current_period_end TIMESTAMPTZ NOT NULL,
  cancelled_at       TIMESTAMPTZ,
  created_at         TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX one_live_subscription_per_account
  ON subscriptions (account_id) WHERE status <> 'cancelled';
```

Notes from the data owner:
- unit_price_cents is the price per seat per billing interval, in the currency's minor unit (cents for EUR and USD, pence for GBP). Supported currencies are EUR, USD and GBP.
- A subscription moves from trialing to active; a failed payment makes it past_due, and it returns to active when payment succeeds or becomes cancelled after 14 days.
- trial_ends_at is NULL when a subscription was created without a trial.
- current_period_end is the end of the period already paid for; the renewal invoice is issued at that moment.
- cancelled_at is set when the status becomes cancelled; the customer keeps access until current_period_end.
