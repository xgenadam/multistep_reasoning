Extend the `stack` package with user-defined words, a call-depth limit and a command-line REPL. Everything from the previous version keeps working exactly as before.

## Definitions

`: NAME BODY ;` defines the word `NAME` (lower-cased, like every word).

- A definition may only appear at the top level of a source, not inside `if`, `begin` or another definition. `NAME` is the token right after `:`; it must be a word that is not `:`, `;`, a control word (`if else then begin until`) or a built-in word (every word in the previous table, including `.` and `depth`).
- The body may use control structures, which must be balanced inside the body.
- A definition takes effect when execution reaches it, in order, so `foo : foo 1 ;` fails with `UnknownWord` at the first `foo`. Defining a word is not a step.
- Words are looked up each time they are called, so a word can call itself, and redefining a word changes what every word that calls it does from then on.
- Calling a user word is one step, and each step inside its body counts as usual. An error inside a body is reported at the token inside the body.
- Definitions persist across calls to `run`. A source with a `ControlError` defines nothing, since nothing runs.
- `Interpreter.defined()` returns the sorted list of user-defined word names.

`ControlError` is also raised, before anything runs, for:

- a `;` with no open definition, or a `;` while an `if` or `begin` inside the definition is still open (reported at the `;`);
- a `:` inside an `if`, a `begin` or another definition (reported at that `:`);
- a `:` that is the last token (reported at the `:`), or whose `NAME` is not allowed (reported at the `NAME` token);
- a definition that is still open at the end of the source: as before, the error is reported at the last opener (`:`, `if` or `begin`) that is still open.

## Call depth

The constructor becomes `Interpreter(max_steps=100000, max_depth=100)`. The call depth is the number of user-word calls in progress. A call that would make it greater than `max_depth` raises `CallDepthExceeded` (a new `StackError` subclass, exported from the package) at the calling token, instead of starting the call. Steps and depth are both counted per call to `run`.

## REPL

`stack/interp.py` gains:

- `repl(infile, outfile, interp=None)`: reads `infile` line by line until it ends, running each line as a separate source in `interp` (a new `Interpreter` if `None`). After each line it writes one line to `outfile`: the values that line appended to the output, separated by spaces, then ` ok` (or just `ok` if there were none); or, if the line raised a `StackError`, `error: CLASSNAME: WORD`, where `CLASSNAME` is the error's class name and `WORD` its `word`. The stack and the definitions carry on to the next line either way. It returns 0.
- `main(argv=None) -> int`, used by `python -m stack.interp`:
  - with no arguments it runs `repl` on stdin and stdout;
  - with one argument, a file path, it runs the whole file as one source, writes the output values separated by spaces on one line to stdout (nothing if there are none), and returns 0. If the source raises a `StackError`, it still writes the output produced before the error, then writes `error: CLASSNAME: WORD at line L, column C` to stderr and returns 1. If the file cannot be read it writes a message starting with `error:` to stderr and returns 2.

Use only the Python 3.12 standard library. Give the complete updated files, each in its own fenced code block, with the file's path on the line just before the block.
