Write a Python module `calc.py` with a function `evaluate(expr: str) -> Fraction` that evaluates an arithmetic expression exactly and reports errors with their position.

The language:
- Numbers are decimal: one or more digits, optionally followed by `.` and one or more digits (`7`, `0.25`, `12.50`). `.5` and `5.` are not numbers. Every number is converted exactly to a `fractions.Fraction` (`0.1` is `Fraction(1, 10)`), and all arithmetic is exact, so `evaluate('0.1 + 0.2') == Fraction(3, 10)`.
- Binary operators `+`, `-`, `*` and `/`, with `*` and `/` binding tighter than `+` and `-`, and operators of the same precedence grouping from the left (`8 - 3 - 2` is `3`, `8 / 4 / 2` is `1`).
- Unary minus, which can be repeated and binds tighter than every binary operator: `-3 * 2`, `2 * -3`, `2 - -3` and `--4` are all valid. There is no unary plus.
- Parentheses for grouping.
- Spaces and tabs are allowed between tokens and are ignored. No other characters are allowed.
- The result is always a `Fraction`, even when it is a whole number.

Errors: `class CalcError(Exception)`, with an attribute `position`, a 0-based index into `expr`.
- A syntax error's position is that of the first token, or the first character that cannot start a token, at which the text stops being the beginning of a valid expression. If the text ends while an expression is still incomplete, the position is `len(expr)`. For example: `'1 + * 2'` → 4, `'1 2'` → 2, `'(1 + 2'` → 6, `'1 + 2)'` → 5, `'()'` → 1, `'2 $ 3'` → 2, `'1.5.2'` → 3, `''` → 0, `'3 +'` → 3.
- Syntax is checked before anything is evaluated, so an expression with a syntax error always raises for the syntax error.
- Division by zero raises `CalcError` with the position of the `/` whose right operand is zero; if there are several, it is the first one met when evaluating left to right. `evaluate('1 + 4 / (2 - 2)')` raises with position 6.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
