Extend the `adventure` package with locked exits, a `use` command for keys, and a score. Everything else keeps working exactly as before, and games saved by the previous version must still load.

## World

- An exit may now be written as a dict instead of a room id: `"north": {"to": "vault", "key": "brass_key"}`. Such an exit is locked at the start of every game and can only be unlocked with the named item. A plain room id is an unlocked exit, as before.
- `Room` gains a field `locks`: a dict from direction to key item id, for the room's locked exits (empty if none). `Room.exits` still maps every direction to its target room id, locked or not.
- An item may have `"treasure": N`, a whole number of points ≥ 0 (default 0). `Item` gains a field `treasure`.
- `from_dict` also raises `WorldError` if an exit dict lacks `to` or `key`, its `to` is not a room, its `key` is not an item, or a `treasure` is not an int ≥ 0.

## Parser

Two new commands:

| Input | Result |
| --- | --- |
| `use X` | `Command('use', X)` |
| `score` | `Command('score', None)` |

`use` with nothing left after removing articles raises `ParseError('Use what?')`, and anything after `score` raises `ParseError("I don't understand that.")`.

## Game

- `go DIR` through an exit that is still locked does not move the player or count as a move; the response is `The way DIR is locked.`
- `use X`: if no matching item is in the inventory, `You aren't carrying that.` Otherwise, if the item is the key of one or more exits of the current room that are still locked, all of those exits are unlocked for the rest of the game and the response is `Unlocked: ` and their directions in `DIRECTIONS` order, joined with `, `, then `.`. Otherwise `Nothing here to use the NAME on.` Unlocking one exit never unlocks any other exit, including the exit back from the other room.
- In the `look` text, each exit that is still locked is listed as `DIR (locked)`, as in `Exits: north (locked), down.`
- Score: entering a room for the first time scores 10 points; the start room counts as visited from the beginning and scores nothing. Taking an item with `treasure` points for the first time scores those points; dropping it and taking it again scores nothing more. `score` responds `Your score is N.` A new property `score` gives the number.

## Saving

- `save()` now writes `"version": 2` and four more keys: `"unlocked"` (a list of `[room_id, direction]` pairs for the exits unlocked so far, sorted), `"visited"` (the sorted list of visited room ids), `"scored"` (the sorted list of item ids whose treasure points have been awarded) and `"score"`.
- `Game.load` accepts version 2 saves, and raises `SaveError` if one of the four new keys is missing, an `unlocked` pair is not a locked exit of the world, a `visited` room or a `scored` item is not in the world, or `score` is not a non-negative integer. It still applies every check from before.
- `Game.load` also accepts version 1 saves, which have none of the four new keys. Such a game has every lock still locked, the start room and the saved current room as its visited rooms, nothing scored, and a score of 0.
- Any other version raises `SaveError`.

Use only the Python 3.12 standard library. Give the complete updated files, each in its own fenced code block, with the file's path on the line just before the block.
