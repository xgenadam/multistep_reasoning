We are releasing version 2 of the Parcelpoint API. Please update the reference so that it documents v2. The changes are below; everything not mentioned stays exactly as it is.

**Base URL.** `https://api.parcelpoint.example/v2`. Every example must use it.

**Authentication changes.** v2 uses OAuth 2.0 client credentials instead of API keys.
- Get a token with `POST https://auth.parcelpoint.example/oauth/token`, form-encoded, with `grant_type=client_credentials`, `client_id`, `client_secret` and `scope` (space-separated). The response is `{"access_token": "...", "token_type": "Bearer", "expires_in": 3600, "scope": "..."}`.
- Send the token on every request as `Authorization: Bearer <token>`. Tokens last 3600 seconds; request a new one when it expires (there are no refresh tokens).
- Scopes: `shipments:read`, `shipments:write`, `pickups:write`, `webhooks:manage`. A request whose token lacks the needed scope gets 403 `forbidden`.
- `X-Api-Key` keeps working on v2 until 31 March 2027 and then stops; after that date it returns 401.
- Document the token request in the Overview's authentication subsection, with a `curl` example; it is not one of the numbered endpoints.

**Three new endpoints** (document them like the others, each with the same four subsections):
1. `GET /pickups/{pickup_id}`: retrieve a pickup. Returns 200 with the Pickup. Errors: 401, 403, 404, 429. Scope: `pickups:write`.
2. `GET /webhooks`: list webhooks (paginated with `limit` and `cursor`; `secret` is never returned). Returns 200. Errors: 401, 403, 429. Scope: `webhooks:manage`.
3. `DELETE /webhooks/{webhook_id}`: delete a webhook. Returns 204 with no body. Errors: 401, 403, 404, 429. Scope: `webhooks:manage`.

Place the pickup endpoint after `DELETE /pickups/{pickup_id}`, and the two webhook endpoints after `POST /webhooks`.

**Two deprecated endpoints.** Keep them documented in their places, but start each one's section with a line "Deprecated: removed on 30 June 2027", followed by what to use instead:
- `GET /shipments/{shipment_id}/tracking`: use the new `tracking_events` field of the Shipment (same event format), returned by `GET /shipments/{shipment_id}`, or the `tracking.updated` webhook.
- `POST /addresses/validate`: send `"validate_addresses": true` in the body of `POST /shipments` instead; invalid addresses then return 422 `validation_failed` with `field` set to `to_address` or `from_address`.

So also add `tracking_events` (array of tracking events) to the Shipment object, and the optional boolean body parameter `validate_addresses` (default false) to `POST /shipments`.

**Scopes per endpoint.** Every endpoint section now states its required scope on a line "Scope: …": reads of shipments, rates and tracking need `shipments:read`; creating, changing, cancelling and labelling shipments and validating addresses need `shipments:write`; pickups need `pickups:write`; webhooks need `webhooks:manage`. Add 403 to every endpoint's error table.
