Our web servers write access logs in two formats: older hosts use the Apache common log format, newer ones write JSON lines. Write a Python package `logagg` that reads both, turns every line into the same normalised record, and prints summary statistics.

Layout:

```
logagg/__init__.py   re-exports Record, ParseError, parse_clf, parse_jsonl, parse_line,
                     read_records, percentile, filter_records, summarize
logagg/parsers.py    Record, ParseError, normalize, parse_clf, parse_jsonl, parse_line, read_records
logagg/stats.py      percentile, filter_records, summarize
logagg/cli.py        main(argv=None) -> int, run as `python -m logagg.cli`
```

## Records and normalisation (`logagg/parsers.py`)

`Record` is a frozen dataclass with fields `time: datetime` (timezone-aware, in UTC), `client: str`, `method: str`, `path: str`, `status: int`, `size: int` and `latency_ms: float | None`.

Both parsers extract the raw fields and pass them to one function, `normalize(time, client, method, path, status, size, latency_ms) -> Record`, so that the same request logged in either format gives an equal `Record`. It applies these rules and raises `ParseError` (a subclass of `ValueError`) when a field is invalid:

- `time` must be a timezone-aware `datetime`; it is converted to UTC.
- `client` must be a non-empty string.
- `method` must be a non-empty string of ASCII letters; it is upper-cased.
- `path` must start with `/`. Everything from the first `?` or `#` on is removed, and runs of `/` are collapsed into one (`//a///b?x=1` → `/a/b`).
- `status` is an int, or a string of digits that is converted to int; it must be from 100 to 599.
- `size` is a non-negative int, or a string of digits; `None` and `"-"` mean 0.
- `latency_ms` is `None` or a non-negative number, stored as a `float`.

**Common log format.** `parse_clf(line)` parses

```
127.0.0.1 - frank [10/Oct/2000:13:55:36 -0700] "GET /apache_pb.gif?x=1 HTTP/1.0" 200 2326
```

that is: client, ident, user, `[time]`, the quoted request line, status, size, and optionally one more field, the response time in whole microseconds (`latency_ms` is that number / 1000; without it, `latency_ms` is `None`). Fields are separated by single spaces. The time is `DD/Mon/YYYY:HH:MM:SS ±HHMM` with English month abbreviations. The request line must be exactly three space-separated parts: method, path, protocol. Anything that does not fit raises `ParseError`.

**JSON lines.** `parse_jsonl(line)` parses one JSON object with the keys `ts` (an ISO 8601 string that includes a UTC offset, or ends in `Z`), `client`, `method`, `path`, `status`, and optionally `bytes` (the size) and `latency_ms`. Other keys are ignored. Invalid JSON, a value that is not an object, a missing required key, a `ts` without an offset, or a field the rules above reject raises `ParseError`.

- `parse_line(line, fmt='auto')`: `fmt` is `'clf'`, `'jsonl'` or `'auto'`, which uses the JSON parser when the line, after leading whitespace, starts with `{`, and the common-log parser otherwise. Any other `fmt` raises `ValueError`.
- `read_records(lines, fmt='auto')` takes an iterable of lines (with or without trailing newlines) and returns `(records, bad)`: the parsed records in input order and the list of 1-based line numbers that raised `ParseError`. Lines that are empty or only whitespace are skipped and are neither records nor bad.

## Statistics (`logagg/stats.py`)

- `percentile(values, p)` uses the nearest-rank method: with the values sorted ascending and `n` of them, it returns the value at 1-based rank `ceil(p / 100 × n)`. It raises `ValueError` if `values` is empty or `p` is not in `(0, 100]`.
- `filter_records(records, since=None, until=None, status=None)` keeps records with `since <= time < until` (aware datetimes; `None` means unbounded) and, if `status` is given, whose status matches it: either a class like `'4xx'` (any status from 400 to 499) or an exact code like `'404'`. A `status` of any other form raises `ValueError`.
- `summarize(records, top=3)` returns a dict with exactly these keys:
  - `"requests"`: the number of records;
  - `"bytes"`: the sum of `size`;
  - `"classes"`: a dict with the keys `"1xx"` to `"5xx"`, in that order, each mapped to its count (zero included);
  - `"codes"`: a dict from each status code that occurs, as a string, to its count, with keys in ascending order;
  - `"latency_ms"`: a dict with keys `"count"` (records with a latency), `"p50"`, `"p95"` and `"max"`, the last three `None` when the count is 0;
  - `"top_paths"`: a list of up to `top` `[path, count]` pairs, most frequent first, ties broken by path in ascending order;
  - `"first"` and `"last"`: the earliest and latest record time as `datetime.isoformat()` strings (`"2000-10-10T20:55:36+00:00"`), or `None` when there are no records.

  `top` must be ≥ 0 (`ValueError` otherwise).

## Command line (`logagg/cli.py`)

```
python -m logagg.cli FILE [FILE ...] [--format auto|clf|jsonl] [--since TIME] [--until TIME]
                                     [--status STATUS] [--top N] [--json]
```

The files are read in order as UTF-8 and their lines are parsed with `--format` (default `auto`). Bad lines are counted over all files, before any filtering; then `--since`/`--until` (ISO 8601 times; one without an offset is taken as UTC) and `--status` filter the records, and the summary is computed with `--top` (default 3).

With `--json`, the output is the summary dict with one more key, `"bad_lines"` (the count), written as `json.dumps(summary, indent=2)` and a newline. Otherwise it is exactly these lines:

```
requests: 6
bad lines: 1
bytes: 4096
status: 1xx=0 2xx=4 3xx=0 4xx=1 5xx=1
latency: p50=12.0 ms p95=80.5 ms max=80.5 ms
top paths:
  3 /index.html
  2 /api/items
```

The latency line shows each value with one decimal place, or reads `latency: n/a` when no record has a latency. Each top path is two spaces, the count, a space and the path; when the list of top paths is empty, the line `top paths:` is followed by the line `  none`.

An unreadable file, a bad `--since`/`--until` time, a bad `--status` or a negative `--top` prints a message starting with `error:` to stderr and exits with code 2. Otherwise the exit code is 0, even when some lines were bad.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
