Write a small text template engine as a Python package `tmpl`, in four files:

- `tmpl/lexer.py`: the error classes, the `Token` type and the tokenizer;
- `tmpl/parser.py`: turns a template into a tree of nodes and reports every syntax error;
- `tmpl/render.py`: renders a parsed template against a context;
- `tmpl/__init__.py`: re-exports the public names.

## Template syntax

A template is text with three kinds of tags:

- `{{ expression }}` outputs a value;
- `{% statement %}` is a control tag (`for`, `if` and their companions);
- `{# comment #}` is dropped.

A tag starts at `{{`, `{%` or `{#` and ends at the first `}}`, `%}` or `#}` respectively after it, even if that is inside quotes. Tags may span several lines. Everything outside tags is text and is copied to the output exactly, including all whitespace and newlines (there is no whitespace trimming). A `{` or `}` that does not start a tag is ordinary text.

### Expressions

A value expression is an atom followed by zero or more filters:

- an atom is a string literal in double or single quotes (no escape sequences; it cannot contain its own quote character), an integer literal (`42`, `-3`), or a variable path: a name (`[A-Za-z_][A-Za-z0-9_]*`) followed by zero or more `.segment` parts, where each segment is a name or a non-negative integer (`user.name`, `rows.0.title`);
- a filter is `|name` or `|name:argument`, where the argument is a string or integer literal. Filters apply from left to right.

Whitespace is allowed between the parts of an expression. The words `and`, `or`, `not` and `in` are reserved and cannot be used as names.

A condition (in `if` and `elif`) combines value expressions with the comparisons `==`, `!=`, `<`, `<=`, `>`, `>=` and the words `not`, `and`, `or`. There is at most one comparison between two value expressions (`a < b < c` is a syntax error) and there are no parentheses. Precedence from loosest to tightest is `or`, `and`, `not`, comparison, so `not a == b` means `not (a == b)` and `a or b and c` means `a or (b and c)`. A bare value expression is tested with Python truthiness. `and` and `or` short-circuit: the right side is not evaluated when the left side already decides the result. `{{ }}` holds a value expression only, never a condition.

### Variables

The context maps names to values. A name that is not defined is `None`. Each `.segment` is applied to the current value:

- on `None` the result is `None`;
- on a mapping (`collections.abc.Mapping`): the value stored under the segment as a string key (`rows.0` looks up the key `"0"`), or `None` if there is none;
- on a list or tuple, with an integer segment: the item at that index, or `None` if it is out of range;
- on any other value, with a name segment that does not start with `_`: the attribute of that name, or `None` if there is none;
- anything else gives `None`.

### Output

`{{ }}` writes its value as text: `None` writes nothing and any other value is written as `str(value)` (so `True` writes `True` and `2.5` writes `2.5`). This "output text" is also what the text filters below work on.

### Filters

- `upper`, `lower`, `trim`: the value's output text upper-cased, lower-cased, or with leading and trailing whitespace removed.
- `length`: `len(value)`; `None` gives `0`.
- `first`, `last`: the first or last item (character, for a string), or `None` if the value is empty or `None`.
- `reverse`: a string reversed, or a list of any other value's items in reverse order; `None` gives `None`.
- `join:"sep"` (a string argument is required): the output text of each item, joined with `sep`; `None` gives `""`.
- `default:literal` (a string or integer argument is required): the argument when the value is `None` or the empty string, otherwise the value unchanged (`0` and `False` are kept).
- `truncate:N` (an integer argument `N >= 0` is required): the output text; if it has more than `N` characters, its first `N` characters followed by `...`.
- `items`: a mapping's `(key, value)` pairs as a list of tuples in the mapping's order (use `pair.0` and `pair.1` to reach them); `None` gives `[]`.

An unknown filter, a missing argument, an argument given to a filter that takes none, or an argument of the wrong kind (a string for `truncate`, an integer for `join`, a negative `truncate`) is a syntax error. A filter applied to a value it cannot handle (for example `length` of an integer or `items` of a list) is a render error.

### Statements

- `{% for NAME in EXPR %}body{% endfor %}`, optionally with `{% else %}empty` before `{% endfor %}`. `EXPR` is a value expression. The body is rendered once per item in iteration order (a mapping gives its keys, `None` gives no items). The `else` part is rendered only when there are no items. Inside the body, `NAME` is the current item and `loop` is a mapping with `index` (1-based), `index0` (0-based), `first` and `last` (booleans) and `length` (the number of items). These two names hide outer values of the same names only inside the body: after `endfor`, the outer values (or their absence) are back. In nested loops, `loop` describes the innermost one. Looping over a value that is not iterable (for example an integer) is a render error.
- `{% if COND %}...{% elif COND %}...{% else %}...{% endif %}` with zero or more `elif` parts and at most one `else`, which must come last. The first branch whose condition is true is rendered; if none is, the `else` part (if any).
- `else`, `endfor` and `endif` take nothing after the word.

### Errors

`tmpl/lexer.py` defines:

- `class TemplateError(Exception)`, the base class;
- `class TemplateSyntaxError(TemplateError)` and `class TemplateRenderError(TemplateError)`, both constructed as `(message: str, lineno: int)`, with attributes `message` and `lineno`, and with `str(error) == f"line {lineno}: {message}"`. The wording of the message is up to you.

`lineno` is 1-based: it is the line on which the offending tag's opening `{{`, `{%` or `{#` stands. Syntax errors are reported as follows:

- a tag with no closing delimiter: the line of the tag;
- an unknown statement (`{% while x %}`), a malformed `for` (`{% for x of y %}`, `{% for in y %}`), an empty or malformed expression or a bad filter: the line of the tag;
- an `elif`, `else`, `endif` or `endfor` that does not continue or close the innermost open block (including a second `else` and an `elif` after `else`): the line of that tag;
- a `for` or `if` that is still open at the end of the template: the line of that `for` or `if`.

A render error carries the line of the tag being evaluated (for an `elif` condition, the line of that `elif`). Comparing values that Python cannot order (`None < 1`, `"a" < 1`) is a render error too. For all of these cases no other exception type may escape.

## Public API

`tmpl/lexer.py`:

- `class Token(typing.NamedTuple)` with the fields `kind: str`, `value: str` and `lineno: int`.
- `tokenize(source: str) -> list[Token]`. The kinds are `"text"` (the value is the raw text), `"var"` (the inside of `{{ }}`) and `"block"` (the inside of `{% %}`); tag values are stripped of surrounding whitespace. Comments produce no token. A text token is never empty, and the text on the two sides of a comment stays as two separate tokens. `lineno` is the line on which the token starts. For example, `tokenize("a{{ x }}\n{% if y %}b{# c #}d")` returns `[Token("text", "a", 1), Token("var", "x", 1), Token("text", "\n", 1), Token("block", "if y", 2), Token("text", "b", 2), Token("text", "d", 2)]`.

`tmpl/parser.py`:

- `parse(source: str) -> list`: the template's top-level nodes (the node classes are yours to design). It raises `TemplateSyntaxError` for every syntax error above, without needing a context.

`tmpl/render.py`:

- `class Template`: `Template(source: str)` parses at once, so the constructor raises the syntax errors. `render(context: dict | None = None, **kwargs) -> str` renders with the context's names plus the keyword arguments (a keyword argument wins over a context entry of the same name). Rendering never modifies the dict passed in, and a template can be rendered any number of times.
- `render(source: str, context: dict | None = None, **kwargs) -> str` is the same as `Template(source).render(context, **kwargs)`.

`tmpl/__init__.py` exports `Template`, `render`, `tokenize`, `parse`, `Token`, `TemplateError`, `TemplateSyntaxError` and `TemplateRenderError`.

For example, rendering

```
{% for u in users %}{{ loop.index }}. {{ u.name|upper }}{% if u.admin %} (admin){% endif %}
{% else %}nobody
{% endfor %}
```

with `users=[{"name": "ada", "admin": True}, {"name": "bob"}]` gives `"1. ADA (admin)\n2. BOB\n"`, and with `users=[]` gives `"nobody\n"`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
