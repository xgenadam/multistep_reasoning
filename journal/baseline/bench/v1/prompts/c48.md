Our sales team exports orders as CSV and wants a command-line report: totals by month, region and/or product, as CSV for spreadsheets or as a markdown table for the wiki. Write it as a Python package `sales`.

Layout:

```
sales/__init__.py    re-exports Sale, RowError, IngestError, parse_sales, read_sales,
                     Group, Report, build_report, to_csv, to_markdown
sales/ingest.py      Sale, RowError, IngestError, parse_sales, read_sales
sales/aggregate.py   FIELDS, Group, Report, parse_month, filter_months, aggregate, build_report
sales/writers.py     to_csv, to_markdown
sales/cli.py         main(argv=None) -> int, run as `python -m sales.cli`
```

Money is handled with `decimal.Decimal` throughout, never `float`.

## Ingestion (`sales/ingest.py`)

The input is CSV (read with the `csv` module) whose first row is a header. The header must contain the columns `date`, `region`, `product`, `units` and `unit_price`, in any order; header names are matched after stripping whitespace and lower-casing. Other columns are ignored.

- `Sale` is a frozen dataclass with fields `date: datetime.date`, `region: str`, `product: str`, `units: int`, `unit_price: Decimal`, and a property `revenue` equal to `units * unit_price`.
- `RowError` is a `NamedTuple` with fields `line: int` and `message: str`. `line` is the line number in the input, where the header is line 1.
- `IngestError` is a subclass of `ValueError`, raised when the input has no header row or the header lacks a required column (the message names the first missing column in the order listed above).
- `parse_sales(text: str)` returns `(sales, errors)`: the valid rows as `Sale`s and the invalid ones as `RowError`s, both in input order. Lines that are completely empty are skipped silently.
- `read_sales(path)` reads the file as UTF-8 (ignoring a leading byte-order mark) and returns the same as `parse_sales`.

Each field is stripped of surrounding whitespace, then validated:

| Field | Valid when |
| --- | --- |
| `date` | exactly `YYYY-MM-DD` (four, two and two digits) and a real calendar date |
| `region`, `product` | not empty |
| `units` | only digits, and at least 1 |
| `unit_price` | digits, optionally followed by `.` and one or two digits (so `5`, `5.5` and `5.50` are valid; `-1`, `5.505`, `.5` and `5.` are not) |

A row with a different number of fields from the header is invalid with the message `row: ` followed by a reason. Otherwise a row's message is the name of its first invalid field, in the order of the table, then `: ` and a reason (for example `units: must be a whole number of at least 1`); the reason wording is up to you. A row produces at most one error.

## Aggregation (`sales/aggregate.py`)

- `FIELDS = ('month', 'region', 'product')`. A sale's `month` is its date as `YYYY-MM`.
- `parse_month(text)` checks that `text` is `YYYY-MM` with a month from 01 to 12 and returns it unchanged; otherwise it raises `ValueError`.
- `filter_months(sales, start=None, end=None)` keeps the sales whose month is between `start` and `end` (`YYYY-MM` strings, both inclusive; `None` means unbounded).
- `Group` is a frozen dataclass with fields `key: tuple[str, ...]`, `units: int`, `orders: int` (the number of sales) and `revenue: Decimal`.
- `aggregate(sales, by)` groups the sales by the fields named in `by` (a tuple of names from `FIELDS`, in the order given, at least one, no repeats; otherwise `ValueError`). Each group's key holds the sales' values for those fields in that order. The result is a list of `Group`s sorted by key.
- `Report` is a frozen dataclass with fields `by: tuple[str, ...]`, `groups: list[Group]` and `total: Group` (the sum over all the sales, with key `()`).
- `build_report(sales, by)` returns the `Report`.

## Writers (`sales/writers.py`)

`to_csv(report)` and `to_markdown(report)` each return a string. Both render the same table, so a spreadsheet and the wiki always agree:

- The columns are the `by` field names in order, then `units`, `orders`, `revenue`, `share`.
- One row per group, in the report's order, then a total row whose first column is `TOTAL`, whose other key columns are empty, and whose numbers are the report's total.
- `revenue` has exactly two decimal places (`1234.50`), with no thousands separator.
- `share` is the row's revenue as a percentage of the total revenue, rounded half up to one decimal place and followed by `%` (`12.5%`, `6.3%` for 6.25 %). Each row is rounded on its own, so the shares need not add up to 100. The total row's share is `100.0%`. If the total revenue is zero, every share, including the total row's, is `0.0%`.

`to_csv` writes the header row and then the rows with `csv.writer` and `lineterminator='\n'` (so a value containing a comma is quoted).

`to_markdown` writes each line as `"| " + " | ".join(cells) + " |"` followed by `"\n"`: first the header line, then an alignment line whose cells are `---` for the key columns and `---:` for the four number columns, then the rows. A `|` inside a cell is written as `\|`.

## Command line (`sales/cli.py`)

```
python -m sales.cli INPUT [--by FIELDS] [--format csv|md] [--from YYYY-MM] [--to YYYY-MM]
                          [--output PATH] [--strict]
```

- `--by` is a comma-separated list of fields (default `month`); `--format` defaults to `csv`.
- `--from` and `--to` keep only the months in that inclusive range.
- The report goes to `--output` (written as UTF-8; nothing is printed on stdout) or to stdout.
- Every row error is printed to stderr as `line N: MESSAGE`, in input order. Without `--strict`, the report is built from the valid rows and the exit code is 0. With `--strict`, any row error means no report is written anywhere (no output file is created) and the exit code is 1.
- These are usage errors, which print a message starting with `error:` to stderr and exit with code 2 without writing a report: an unknown or repeated `--by` field, a bad `--from`/`--to` month, `--from` later than `--to`, an input file that cannot be read, and an `IngestError`. Errors in the arguments themselves may be left to `argparse`, which also exits with code 2.
- If no sales remain, the report has only the header and the total row (with zero units, orders and revenue).

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
