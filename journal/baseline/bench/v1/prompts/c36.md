Write a small Python package `minisql` that runs simple SQL `SELECT` queries over in-memory tables. A table is a list of dicts (one dict per row); a database is a dict mapping table names to tables. The package has four files:

- `minisql/__init__.py` re-exports `Token`, `tokenize`, `parse`, `execute`, `query`, `SQLError`, `SQLSyntaxError`, `SQLExecutionError`, `Select`, `Column`, `Literal`, `Compare`, `And`, `Or`, `Not` and `IsNull`.
- `minisql/tokens.py`: the exceptions and the tokenizer.
- `minisql/parser.py`: the syntax tree classes and the parser.
- `minisql/execute.py`: the executor and `query`.

## The language

```
SELECT select_list FROM table [WHERE condition] [ORDER BY order_item {, order_item}] [LIMIT n]
select_list := * | name {, name}
order_item  := name [ASC | DESC]
condition   := condition OR condition | condition AND condition | NOT condition
             | ( condition ) | operand op operand | operand IS [NOT] NULL
operand     := name | number | string | NULL | TRUE | FALSE
op          := = | != | <> | < | <= | > | >=
```

- `NOT` binds tighter than `AND`, which binds tighter than `OR`. `AND` and `OR` are left-associative: `a = 1 OR b = 2 OR c = 3` is `Or(Or(a = 1, b = 2), c = 3)`. Parentheses group conditions only (an operand cannot be parenthesised). A bare operand is not a condition.
- The clauses must appear in the order shown, each at most once, and the statement ends after the last clause. Anything else is a syntax error.
- `n` in `LIMIT` is a non-negative integer literal.
- The same name listed twice in the select list is a syntax error.

## `minisql/tokens.py`

- `class SQLError(Exception)`: the base of both error types.
- `class SQLSyntaxError(SQLError)`: raised by `tokenize` and `parse`. It has an attribute `pos`, the 0-based character offset in the SQL text of the character or token where the problem was found (`len(sql)` when the statement ends too early). Construct it as `SQLSyntaxError(message, pos)`.
- `@dataclass(frozen=True) class Token` with fields `kind: str`, `value` and `pos: int` (the offset of the token's first character).
- `tokenize(sql: str) -> list[Token]` returns every token in order, followed by one `Token('EOF', None, len(sql))`. Whitespace separates tokens and is otherwise ignored. Kinds and values:
  - `KEYWORD`: one of `SELECT FROM WHERE AND OR NOT ORDER BY ASC DESC LIMIT IS NULL TRUE FALSE`, matched case-insensitively; the value is the keyword in upper case.
  - `IDENT`: any other word matching `[A-Za-z_][A-Za-z0-9_]*`; the value is the word exactly as written (names are case-sensitive).
  - `NUMBER`: digits with an optional fractional part (`12`, `3.25`), optionally preceded directly by `-` (`-4`). The value is an `int` when there is no `.`, else a `float`. A `.` must have digits on both sides; a `.` without them is an error at the `.`.
  - `STRING`: text in single quotes; two single quotes inside stand for one quote (`'it''s'` is `it's`). The value is the text without the quotes. An unterminated string is a syntax error at the opening quote.
  - `OP`: one of `= != <> < <= > >=`; `<>` is returned with the value `'!='`.
  - `STAR` (`*`), `COMMA` (`,`), `LPAREN` (`(`), `RPAREN` (`)`), each with the character as its value.
  - Any other character is a syntax error at that character.

## `minisql/parser.py`

All syntax tree classes are `@dataclass(frozen=True)` with exactly these fields, in this order:

- `Column(name: str)`, `Literal(value)` (an `int`, `float`, `str`, `bool`, or `None` for `NULL`);
- `Compare(op: str, left, right)` where `op` is one of `= != < <= > >=`;
- `And(left, right)`, `Or(left, right)`, `Not(operand)`;
- `IsNull(operand, negated: bool)` (`negated` is true for `IS NOT NULL`);
- `Select(columns, table: str, where, order_by: list, limit)`: `columns` is `None` for `*`, else the list of names in order; `where` is the condition or `None`; `order_by` is a list of `(name, descending)` tuples (empty when there is no `ORDER BY`); `limit` is an `int` or `None`.

`parse(sql: str) -> Select` tokenizes and parses one statement, raising `SQLSyntaxError` at the first token that does not fit.

## `minisql/execute.py`

- `class SQLExecutionError(SQLError)`: raised by `execute` for the problems listed below.
- `execute(stmt: Select, tables: dict[str, list[dict]]) -> list[dict]` runs a parsed statement. `query(sql: str, tables: dict[str, list[dict]]) -> list[dict]` is `execute(parse(sql), tables)`.

Rules:

1. An unknown table name raises `SQLExecutionError`.
2. A column that is missing from a row reads as `NULL` (`None`) in that row. Unknown columns are never an error.
3. Values have three kinds: numbers (`int` or `float`, but not `bool`), strings and booleans. `NULL` is not a value of any kind.
4. Comparisons use three-valued logic. If either side is `NULL`, any `op` comparison is unknown. Two values of the same kind compare as Python compares them (strings case-sensitively, `False < True`). For values of different kinds, `=` is false, `!=` is true, and `<`, `<=`, `>`, `>=` raise `SQLExecutionError`.
5. `NOT` of unknown is unknown. `AND` is false if either side is false, otherwise unknown if either side is unknown, otherwise true. `OR` is true if either side is true, otherwise unknown if either side is unknown, otherwise false. `IS NULL` and `IS NOT NULL` are always true or false.
6. `WHERE` keeps the rows whose condition is true (not unknown).
7. `ORDER BY` sorts the kept rows by the first item, then the second, and so on; each item is ascending unless `DESC` is given. The sort is stable: rows that tie on every item keep their order in the table. `NULL` sorts before every value in ascending order and after every value in descending order. If the non-`NULL` values of an ordering column in the kept rows are of different kinds, `execute` raises `SQLExecutionError`. The ordering columns do not have to be in the select list.
8. `LIMIT n` keeps the first `n` rows after sorting.
9. Each result row is a new dict. With `*` it is a shallow copy of the table row (same keys, same order). With a select list it has exactly the listed names as keys, in the listed order, with `None` for columns the row lacks.
10. The input tables and rows are never modified.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
