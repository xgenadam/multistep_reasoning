I maintain the public API of Parcelpoint, a shipping platform that lets online shops create shipments, buy labels and track parcels across several carriers. Our API reference is out of date and partly wrong, so I am rewriting it from the spec below. Please write the complete reference, about 7,000 words.

The readers are developers integrating with us. Be exact and consistent: every endpoint documented the same way, every example valid JSON that matches the fields described. Document only what the spec below defines: do not invent endpoints, parameters, fields, headers or status codes.

**General.**
- Base URL: `https://api.parcelpoint.example/v1`. HTTPS only. Request and response bodies are JSON (`Content-Type: application/json`).
- Authentication: every request sends an API key in the `X-Api-Key` header. Keys starting `pp_test_` work in the sandbox; `pp_live_` keys in production.
- Rate limit: 600 requests per minute per key. Every response carries `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset` (Unix seconds).
- Pagination: list endpoints take `limit` (1–100, default 20) and `cursor`; responses contain `data` (array) and `next_cursor` (string, or null on the last page).
- Idempotency: POST requests may send an `Idempotency-Key` header; repeating a request with the same key within 24 hours returns the original response.
- Timestamps are ISO 8601 in UTC. Weights are in grams, dimensions in centimetres, and money is an object `{"amount": "12.40", "currency": "EUR"}`.
- Errors have the body `{"error": {"code": "...", "message": "...", "field": "..."}}` (`field` only for validation errors). The status codes are exactly: 400 `invalid_request`, 401 `unauthorized`, 403 `forbidden`, 404 `not_found`, 409 `conflict`, 422 `validation_failed`, 429 `rate_limited`, 500 `internal_error`.

**Objects.**
- Shipment: `id` (string, `shp_…`), `status` (`draft`, `label_purchased`, `in_transit`, `delivered`, `cancelled`), `from_address`, `to_address` (Address), `parcels` (array of Parcel), `carrier` (string or null), `service` (string or null), `reference` (string, optional, up to 64 characters), `label_url` (string or null), `tracking_number` (string or null), `created_at`, `updated_at`.
- Address: `name`, `company` (optional), `line1`, `line2` (optional), `city`, `postal_code`, `country` (ISO 3166-1 alpha-2), `phone` (optional), `email` (optional).
- Parcel: `weight_g` (integer, 1–30,000), `length_cm`, `width_cm`, `height_cm` (integers, 1–150).
- Rate: `carrier`, `service`, `price` (money), `estimated_days` (integer).
- Pickup: `id` (`pck_…`), `carrier`, `address`, `date` (YYYY-MM-DD), `window_start`, `window_end` (HH:MM), `shipment_ids`, `status` (`scheduled`, `cancelled`).
- Webhook: `id` (`whk_…`), `url`, `events` (array), `secret` (returned only on creation), `created_at`.

**The twelve endpoints.**
1. `POST /shipments`: create a shipment in `draft`. Body: `from_address`, `to_address`, `parcels` (all required), `reference` (optional). Returns 201 with the Shipment. Errors: 400, 401, 422, 429.
2. `GET /shipments`: list shipments, newest first. Query: `status` (optional), `created_after` (optional timestamp), `limit`, `cursor`. Returns 200. Errors: 400, 401, 429.
3. `GET /shipments/{shipment_id}`: retrieve one shipment. Returns 200. Errors: 401, 404, 429.
4. `PATCH /shipments/{shipment_id}`: update `to_address`, `parcels` or `reference`, only while `status` is `draft`. Returns 200. Errors: 400, 401, 404, 409 (not in `draft`), 422, 429.
5. `POST /shipments/{shipment_id}/cancel`: cancel a shipment; allowed in `draft` or `label_purchased` (the label cost is refunded). Returns 200 with the Shipment in `cancelled`. Errors: 401, 404, 409, 429.
6. `POST /shipments/{shipment_id}/rates`: get rates for a draft shipment from all enabled carriers. No body. Returns 200 with `data` (array of Rate). Errors: 401, 404, 409, 429.
7. `POST /shipments/{shipment_id}/label`: buy a label. Body: `carrier`, `service` (required, from a rate), `format` (`pdf` or `zpl`, default `pdf`). Returns 200 with the Shipment in `label_purchased`, with `label_url` and `tracking_number`. Errors: 400, 401, 404, 409, 422, 429.
8. `GET /shipments/{shipment_id}/tracking`: tracking events, oldest first: each event has `status`, `description`, `location` (string or null), `occurred_at`. Returns 200. Errors: 401, 404, 429.
9. `POST /addresses/validate`: body is an Address. Returns 200 with `valid` (boolean), `suggested` (Address or null) and `messages` (array of strings). Errors: 400, 401, 422, 429.
10. `POST /pickups`: schedule a carrier pickup. Body: `carrier`, `address`, `date`, `window_start`, `window_end`, `shipment_ids` (all required; every shipment must be `label_purchased` with that carrier). Returns 201 with the Pickup. Errors: 400, 401, 409, 422, 429.
11. `DELETE /pickups/{pickup_id}`: cancel a pickup, up to 2 hours before `window_start`. Returns 204 with no body. Errors: 401, 404, 409, 429.
12. `POST /webhooks`: register a webhook. Body: `url` (HTTPS, required), `events` (required, from `shipment.updated`, `tracking.updated`, `pickup.updated`). Returns 201 with the Webhook including `secret`. Deliveries are signed with HMAC-SHA256 of the raw body in the `Parcelpoint-Signature` header. Errors: 400, 401, 422, 429.
