Write a small finite-state-machine library, the package `fsm/`, and a vending machine `vending.py` built on it. There are three files: `fsm/__init__.py`, `fsm/machine.py` and `vending.py`.

## `fsm/machine.py`

Exceptions:
- `MachineError(Exception)`: the base class.
- `InvalidTransition(MachineError)`: raised by `fire` when no transition for the event leaves the current state. Its attributes `state` and `event` hold the current state name and the event name.
- `GuardRejected(MachineError)`: raised by `fire` when at least one transition for the event leaves the current state but every one of them was rejected by its guard. Same `state` and `event` attributes.

Data classes (from `dataclasses`):
- `State(name: str, on_enter=None, on_exit=None)`.
- `Transition(event: str, source, target, guard=None, action=None)`. `source` is a state name, a list or tuple of state names, or the string `'*'`, which matches every state. `target` is a state name, or `None` for an internal transition (see below).
- `Event(name: str, source: str, target: str, data: dict)`: what hooks receive. `source` is the current state; `target` is the state the transition leads to (for an internal transition, the current state).

Every hook (`guard`, `action`, `on_enter`, `on_exit`) is called as `hook(machine, event)`, where `machine` is the `Machine` and `event` is an `Event`. A guard returns a truthy value to allow its transition.

`Machine(states, transitions, initial: str, context=None)`:
- `states` is a list whose items are `State` objects or plain names (a plain name is a state with no hooks). `transitions` is a list of `Transition`.
- Raises `ValueError` if `states` is empty, if two states share a name, if `initial` is not a state, or if a transition names a source or target that is not a state.
- Attributes: `state` (the current state's name, starting at `initial`), `context` (the object given, for hooks to use) and `history`, a list of `(source, event, target)` tuples, one per transition taken, oldest first; an internal transition is recorded with `target` equal to `source`.
- The constructor runs no hooks.

`fire(event: str, **data) -> str` takes one transition and returns the new current state:
1. The candidates are the transitions whose `event` matches and whose `source` matches the current state, in the order they were given to the constructor. If there are none, raise `InvalidTransition`.
2. One `data` dict holding the keyword arguments is created per call; every `Event` built during the call shares that same dict object, so hooks can pass values to later hooks through it.
3. The guards are evaluated in candidate order; the first candidate with no guard, or whose guard returns a truthy value, is taken. Later guards are not called. If every candidate is rejected, raise `GuardRejected`; nothing else has run and the state is unchanged.
4. For a normal transition, run in this order: the current state's `on_exit`, the transition's `action`, then set `state` to the target and append to `history`, then the target state's `on_enter`, then every listener added with `on_transition`, in the order they were added, called as `listener(source, event, target)`. A transition whose target is its own source still runs `on_exit` and `on_enter`.
5. An internal transition (`target=None`) runs only its `action`, records history and calls the listeners; it runs no `on_exit` or `on_enter` and the state stays the same.
6. An exception raised by any hook propagates unchanged out of `fire`. If it comes from a guard, `on_exit` or the action, the state and `history` are unchanged. If it comes from `on_enter` or a listener, the state has already changed.
7. Calling `fire` on a machine while one of its `fire` calls is still running (from inside a hook) raises `MachineError`. A `fire` that ended with an exception leaves the machine usable.

Other methods:
- `can_fire(event: str, **data) -> bool`: whether `fire` with the same arguments would take a transition now. It calls guards (they must not have side effects) but no other hooks, and never raises `InvalidTransition` or `GuardRejected`.
- `available_events() -> list[str]`: the sorted, de-duplicated names of the events that have at least one transition from the current state, ignoring guards.
- `on_transition(listener)`: adds a listener.
- `reset()`: sets the state back to `initial` and clears `history`. It runs no hooks.

`fsm/__init__.py` re-exports `Machine`, `State`, `Transition`, `Event`, `MachineError`, `InvalidTransition` and `GuardRejected`.

## `vending.py`

`VendingMachine(products: dict[str, tuple[int, int]])` maps a product code to `(price, stock)`, prices in cents. It must be built on `fsm`: its attribute `machine` is the `fsm.Machine` it uses, and `machine.state` is always equal to the vending machine's `state`. The states are `'idle'`, `'credit'` (money has been inserted) and `'maintenance'`. A vending machine starts in `'idle'` with 0 credit.

Accepted coins are 5, 10, 25 and 100 cents. Change and refunds are paid greedily from the largest coin down (100, 25, 10, 5), as a list in that descending order; the machine never runs out of change.

Exceptions in `vending.py`: `VendingError(Exception)`, `SoldOut(VendingError)` and `InsufficientCredit(VendingError)`. Operations that are not allowed in the current state raise `fsm.InvalidTransition` (they are simply missing from the machine's transition table).

| Method | Allowed in | Effect and return value |
| --- | --- | --- |
| `insert(coin: int) -> int` | `idle`, `credit` | Adds the coin to the credit, moves to `credit`, returns the new credit. A coin that is not accepted raises `ValueError` and changes nothing. |
| `select(code: str) -> list[int]` | `credit` | Sells one unit: stock goes down by 1, the credit minus the price is returned as change, the credit becomes 0 and the state `idle`. |
| `cancel() -> list[int]` | `credit` | Refunds the whole credit as coins; credit 0, state `idle`. |
| `service() -> None` | `idle` | Enters `maintenance`. |
| `restock(code: str, qty: int, price: int \| None = None) -> None` | `maintenance` | Adds `qty` (≥ 1, else `ValueError`) to the stock. A new code needs a `price` (`KeyError` without one); for an existing code a given `price` replaces the old one. |
| `resume() -> None` | `maintenance` | Back to `idle`. |

For `select`, the checks run in this order: the state (`fsm.InvalidTransition` outside `credit`), an unknown code (`KeyError`), no stock left (`SoldOut`), credit below the price (`InsufficientCredit`). A failed `select` leaves the credit, the stock and the state unchanged.

Read-only views: the properties `state` and `credit`, `stock(code) -> int` (`KeyError` for an unknown code), `price(code) -> int` (`KeyError` likewise), `sales() -> dict[str, int]` (units sold per code, only codes sold at least once) and the property `revenue` (total cents of the prices of everything sold).

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
