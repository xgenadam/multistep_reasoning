Write a Python module `ledger.py` that reads a CSV file of bank transactions and computes running balances per account, refusing any transaction that would overdraw an account.

- `class LedgerError(Exception)`, with an attribute `line`: the line number in the CSV text that caused the error (the header is line 1).
- `class OverdraftError(LedgerError)`, with the extra attributes `account` (the account name) and `balance` (the `Decimal` balance the transaction would have produced).
- `Transaction` is a frozen dataclass with the fields `date` (`datetime.date`), `account` (`str`), `amount` (`decimal.Decimal`) and `line` (`int`, the line the row came from).
- `parse(text: str) -> list[Transaction]` parses CSV text (read with the `csv` module):
  - The first row is a header that must contain the columns `date`, `account` and `amount`, in any order; other columns are ignored. A missing column raises `LedgerError` with `line` 1. Empty text also raises `LedgerError` with `line` 1.
  - `date` is `YYYY-MM-DD`; `account` is stripped of surrounding spaces and must not be empty; `amount` is a decimal number such as `120`, `-45.5` or `+3.25`, with at most two digits after the point (surrounding spaces are allowed). Anything else in a row, including a row with too few fields, raises `LedgerError` whose `line` is that row's line.
  - Blank lines are skipped but still count as lines. Rows are returned in file order.
- `running_balances(transactions, opening=None, limits=None) -> list[tuple[Transaction, Decimal]]`:
  - Transactions are applied in date order; transactions on the same date keep their order in the input list.
  - `opening` maps account names to opening balances (missing accounts start at `Decimal('0')`). `limits` maps account names to overdraft limits (missing accounts have limit `Decimal('0')`). An account with limit `L` may go down to exactly `-L` but not below.
  - It returns one `(transaction, balance after it)` pair per transaction, in the order they were applied.
  - The first transaction that would take its account below `-limit` raises `OverdraftError` with that transaction's `line`, its `account`, and the balance it would have produced.
- `final_balances(transactions, opening=None, limits=None) -> dict[str, Decimal]` returns the balance of every account after all transactions, under the same rules (including the overdraft check). Accounts that appear only in `opening` are included.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
