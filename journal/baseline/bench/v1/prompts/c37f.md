Extend `md2html` with tables and nested lists. Every other rule stays exactly as before; the changes are below.

## Tables

A table is a new block rule that comes after lists (rule 5) and before paragraphs, so the block rules are now: 1 fenced code, 2 heading, 3 horizontal rule, 4 blockquote, 5 list, 6 table, 7 paragraph.

- **Splitting a row into cells.** Strip the line of surrounding whitespace, remove one leading `|` if there is one and one trailing `|` if there is one (unless it is escaped as `\|`), then split at every `|` that is not preceded by a backslash. Each cell is stripped of surrounding whitespace, and every `\|` inside it becomes `|`. So `| a | b |`, `a | b` and `|a|b` all give the cells `a` and `b`, and `x \| y | z` gives `x | y` and `z`.
- **Start.** A table starts at a line that does not begin with a space, contains a `|`, and is directly followed by a delimiter row with the same number of cells. A delimiter row is a line whose cells (split as above) all match `:?-+:?` (one or more `-`, with an optional `:` at either end). If the counts differ, or the next line is not a delimiter row, the line is not a table start.
- The delimiter row sets each column's alignment: `:--` is `"left"`, `--:` is `"right"`, `:-:` is `"center"` and `--` is `None`.
- **Body rows.** Every following line is a body row while it is not blank, contains a `|`, and does not start a block by rules 1–5. A row with fewer cells than the header is padded with empty cells; extra cells are dropped.
- A table start also ends a paragraph: a paragraph now stops before a line that starts a block by rules 1–6.
- Shape: `("table", aligns, header, rows)`, where `aligns` is the list of alignments, `header` is the list of header cell texts and `rows` is a list of lists of cell texts (after the `\|` replacement, before inline rendering).
- HTML: each tag on its own line, joined with `"\n"`:

  ```
  <table>
  <thead>
  <tr>
  <th>Name</th>
  <th align="right">Qty</th>
  </tr>
  </thead>
  <tbody>
  <tr>
  <td>apple</td>
  <td align="right">3</td>
  </tr>
  </tbody>
  </table>
  ```

  Cells are rendered with `render_inline`. A column with an alignment gets `align="left"`, `align="right"` or `align="center"` on its `<th>` and every `<td>`; a column without one gets no attribute. A table with no body rows has no `<tbody>` element at all: `</thead>` is followed directly by `</table>`.

## Nested lists

- Inside a list, a line whose content after its leading spaces is a list item marker (rule 5's markers) is now an item, even when it is indented. Its indent is the number of leading spaces. A list still can only start at a line that does not begin with a space, and the top-level list's indent is 0.
- Each open list has the indent of its first item. For a marker line with indent D, close nested lists (innermost first) while the innermost open list's indent is greater than D (the top-level list is never closed this way). Then, with the innermost open list L:
  - if D is greater than L's indent, the line starts a new list nested in L's last item;
  - if D equals L's indent and the marker is of L's kind, it adds an item to L;
  - if D equals L's indent and the kind differs: for a nested L, L is closed and a new list starts in its place, as another child of the same item; for the top-level list, the whole list ends there (as before, the line then starts a new list).
- A line that is not a marker line is a continuation: it is stripped and appended (after a `"\n"`) to the last item of the innermost open list.
- The whole list, nested lists included, ends at a blank line, or at a line that does not begin with a space and starts a block by rules 1–4 or 6.
- Item shape changes: each entry of `items` is now a tuple `(text, children)`, where `children` is the list of the item's nested `("list", ...)` blocks in order (`[]` when it has none). So `parse_blocks("- a\n  - b\n- c")` gives `[("list", False, None, [("a", [("list", False, None, [("b", [])])]), ("c", [])])]`.
- HTML: an item without children renders as before. An item with children renders as `<li>`, the inline text, a newline, its children rendered with `render_blocks` (joined with newlines), a newline and `</li>`. For the example above:

  ```
  <ul>
  <li>a
  <ul>
  <li>b</li>
  </ul>
  </li>
  <li>c</li>
  </ul>
  ```

Use only the Python 3.12 standard library. Give the complete updated files, each in its own fenced code block, with the file's path on the line just before the block.
