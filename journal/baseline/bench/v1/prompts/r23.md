Write a runbook for restoring our production PostgreSQL database from a nightly base backup. On-call engineers will follow it, possibly at 3 a.m. and possibly for the first time, so every step must be unambiguous.

Our setup:
- PostgreSQL 16 on Ubuntu 22.04, on the host db-prod-02. The cluster runs under systemd as the unit postgresql@16-main.
- Data directory: /var/lib/postgresql/16/main, owned by postgres:postgres with mode 0700. It holds about 180 GB; the filesystem has 600 GB in total.
- Base backups are taken nightly at 01:00 UTC with pg_basebackup in tar format with gzip compression and the WAL streamed in. Each night's backup is a directory such as /backups/base/2026-03-14/ containing base.tar.gz, pg_wal.tar.gz, backup_manifest and a SHA256SUMS file (check it with `sha256sum -c SHA256SUMS` from inside the directory).
- The application is the systemd service ledger-api on app-01 and app-02; it must be stopped before the restore and started again only after the database checks pass.
- The current data directory must never be deleted: move it aside so it can be recovered.

Use these markdown sections: Purpose and scope, Preconditions, Procedure, Abort criteria, After the restore.

- Preconditions: a bulleted list of what must be true before the engineer starts.
- Procedure: a numbered list of 8 to 12 steps. Each step gives the exact command or commands in a code block and ends with a line starting "Verify:" that says how to confirm the step worked before moving on.
- Abort criteria: a bulleted list of at least three conditions under which the engineer stops and escalates to the database lead in the #db-oncall channel, rather than improvising.
- After the restore: what to check and who to tell before the incident is closed.

Aim for about 600-800 words, commands included.
