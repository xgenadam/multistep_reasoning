Write a Python module `fmt.py` that fills simple templates such as `'Hello {name}, you have {count:no} new messages'`. There are no expressions, attribute lookups or format specs.

- `{name}` is a placeholder. A name starts with an ASCII letter or `_` followed by ASCII letters, digits or `_`.
- `{name:default}` is a placeholder with a default: everything after the first `:` up to the closing `}` is the default text, used when `name` is missing from the values. The default may be empty and may contain `:`, but not `{` or `}`.
- `{{` produces a literal `{` and `}}` a literal `}`, anywhere in the template.
- `render(template: str, values: Mapping[str, object]) -> str` replaces each placeholder with `str(values[name])` if `name` is in `values` (even when the value is an empty string or `None`), else with its default. Substituted text is never scanned again, so a value containing `{x}` is output as is.
- `placeholders(template: str) -> list[str]` returns the placeholder names in order of first appearance, each once.
- Errors:
  - `class TemplateError(ValueError)` with an attribute `position`: the 0-based index in the template of the character where the problem was found. It is raised for a `{` that does not start a valid placeholder (an invalid or empty name, or no closing `}`), with `position` at that `{`, and for a single `}` that is not part of `}}` and does not close a placeholder, with `position` at that `}`.
  - `class MissingKey(KeyError)` with an attribute `name`, raised by `render` when a placeholder without a default names a key that is not in `values`.
  - Both `render` and `placeholders` check the whole template's syntax, scanning left to right and reporting the first problem, before any value is looked up; so a malformed template raises `TemplateError` even if a key is also missing.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
