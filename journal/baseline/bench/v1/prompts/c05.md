Write a Python module `intervals.py` with operations on sets of integers represented as lists of half-open intervals.

An interval is a pair `(start, end)` of integers standing for the integers `start <= x < end`. A pair with `start == end` is empty and contributes nothing. A pair with `start > end` is invalid.

Every function takes intervals as any iterable of 2-item tuples or lists, in any order, possibly overlapping. Every function returns a new list of tuples in normal form: sorted by `start`, with no empty intervals, and coalesced, meaning that intervals that overlap or touch (`(1, 3)` and `(3, 5)`) are merged into one, so that any two consecutive results `(a, b)`, `(c, d)` have `b < c`. The functions never modify their arguments. Any invalid interval in any argument raises `ValueError`.

- `merge(intervals) -> list[tuple[int, int]]`: the normal form of the union of `intervals`. `merge([(5, 8), (1, 3), (2, 4), (8, 9), (6, 6)]) == [(1, 4), (5, 9)]`.
- `insert(intervals, new) -> list[tuple[int, int]]`: the union of `intervals` and the single interval `new`, in normal form.
- `remove(intervals, cut) -> list[tuple[int, int]]`: the integers of `intervals` that are not in the single interval `cut`, in normal form. `remove([(0, 10)], (3, 5)) == [(0, 3), (5, 10)]`.
- `intersect(a, b) -> list[tuple[int, int]]`: the integers that are in both `a` and `b`, in normal form. Intervals that only touch share no integer, so `intersect([(0, 5)], [(5, 9)]) == []`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
