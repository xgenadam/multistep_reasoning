Write an interpreter for a small Forth-like stack language in Python, as a package `stack`.

Layout:

```
stack/__init__.py   re-exports Token, tokenize, Interpreter, evaluate and the error classes
stack/lexer.py      Token, tokenize(source)
stack/interp.py     the error classes, Interpreter, evaluate(source)
```

## Lexer (`stack/lexer.py`)

`Token` is a `NamedTuple` with fields `kind` (`'number'` or `'word'`), `value`, `line` and `col` (1-based, of the token's first character). `tokenize(source)` splits the source on whitespace. A token that is exactly an optional `-` followed by one or more ASCII digits is a number, and its value is the `int`; any other token is a word, and its value is the token lower-cased (so `DUP` and `dup` are the same word, and `-` and `3x` are words). A token that starts with `#` begins a comment: it and the rest of its line are skipped.

## Language

The interpreter has a data stack of ints and an output list. Below, stack effects are written `( before -- after )` with the top of the stack on the right.

| Word | Effect |
| --- | --- |
| a number | push it |
| `+` `-` `*` | `( a b -- a+b )`, `( a b -- a-b )`, `( a b -- a*b )` |
| `/` `mod` | `( a b -- a//b )`, `( a b -- a%b )` with Python's floor semantics; `b == 0` raises `DivisionByZero` |
| `negate` `abs` | `( a -- -a )`, `( a -- abs(a) )` |
| `dup` `drop` `swap` `over` `rot` | `( a -- a a )`, `( a -- )`, `( a b -- b a )`, `( a b -- a b a )`, `( a b c -- b c a )` |
| `=` `<>` `<` `>` | `( a b -- flag )`: is `a = b`, `a ≠ b`, `a < b`, `a > b` |
| `0=` | `( a -- flag )`: is `a = 0` |
| `and` `or` | `( a b -- n )`: the bitwise and, or the bitwise or, of `a` and `b` |
| `depth` | `( -- n )`: the number of items on the stack before this word |
| `.` | `( a -- )`: append `a` to the output |

A flag is `-1` for true and `0` for false; any non-zero value counts as true.

Control structures:

- `if A then` and `if A else B then`: `if` pops a value and runs `A` if it is non-zero, else `B` (if present).
- `begin A until`: runs `A`, then `until` pops a value; if it is zero the loop runs `A` again, otherwise the loop ends.
- They nest freely.

## Interpreter (`stack/interp.py`)

Errors: `StackError(Exception)` is the base class, with attributes `word` (the token's text, lower-cased), `line` and `col` (the token's position). Subclasses:

- `StackUnderflow`: a word, `if` or `until` needs more items than the stack holds. The stack is left exactly as it was before that word.
- `UnknownWord`: a word that is not defined, raised when it is executed.
- `DivisionByZero`: as above.
- `ControlError`: the control structure is malformed: a `then` or `else` with no open `if`, a second `else` for the same `if`, an `until` with no open `begin`, a closer that does not match the innermost open structure (as in `if begin then`, reported at the `then`), or a structure left open at the end of the source (reported at the last opener that is still open). The whole source is checked before anything runs, so a `ControlError` means nothing ran; the first problem met reading left to right is the one reported.
- `StepLimitExceeded`: see below.

`Interpreter(max_steps=100000)` has the attributes `stack` (a list, bottom first) and `output` (a list of ints).

- `run(source)` runs the source. The stack and output persist across calls to `run`.
- Each number pushed, each word executed and each `if` and `until` evaluated is one *step*; `else`, `then` and `begin` are not steps. If running a source would take more than `max_steps` steps (counted per call to `run`), the step that would exceed the limit raises `StepLimitExceeded` at its token instead of running.
- When a run raises (other than `ControlError`), everything done before the failing token stays done: the stack and output keep those changes.

`evaluate(source)` runs `source` in a new `Interpreter` and returns its stack.

For example, `evaluate('10 0 begin over + swap 1 - swap over 0= until swap drop')` sums 10 + 9 + … + 1 and returns `[55]`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
