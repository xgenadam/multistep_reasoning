Add strict-mode options to the `js` package: a policy for repeated object keys, a nesting-depth limit, and opt-in support for `NaN` and the infinities. With every new option left at its default, everything behaves exactly as before, and every error position and error rule from before still holds.

The signatures become:

```python
tokenize(text, *, allow_nan=False)
loads(text, *, duplicate_keys='last', max_depth=None, allow_nan=False)
dumps(obj, *, indent=None, sort_keys=False, ensure_ascii=False, allow_nan=False)
```

The package layout and the exports stay the same.

## Repeated keys

`duplicate_keys` is one of:

- `'last'` (the default): a repeated key keeps its last value, in the position where the key first appeared;
- `'first'`: a repeated key keeps its first value and later ones are ignored;
- `'error'`: a repeated key raises `JSONError` pointing at the opening quote of the repeated key. The key is checked as soon as it is read, before its value is parsed.

Keys are compared after decoding, so `"a"` and `"a"` are the same key. Each object is checked on its own; the same key in two different objects is fine. Any other value of `duplicate_keys` raises `ValueError` before the text is read.

## Depth limit

`max_depth` is `None` (no limit) or an int ≥ 1; anything else (0, a negative number) raises `ValueError` before the text is read. A top-level array or object has depth 1, and a container directly inside a container of depth `d` has depth `d + 1`; scalars have no depth. A container whose depth would be greater than `max_depth` raises `JSONError` pointing at its opening `[` or `{`, as soon as that bracket is read. So with `max_depth=2`, `[[1]]` and `[{}, [2]]` parse, `[[[1]]]` is an error at the third character, and `7` parses with `max_depth=1`.

## NaN and infinities

- With `allow_nan=True`, the scanner reads `NaN`, `Infinity` and `-Infinity` as `'NUMBER'` tokens whose values are `float('nan')`, `float('inf')` and `float('-inf')`. The letter-run rule still applies: the whole run of ASCII letters must be exactly `NaN` or `Infinity` (or `true`, `false`, `null`); otherwise it is an "invalid literal" error at its first letter. A `-` followed by a run of letters is `-Infinity` if the run is exactly `Infinity`, and otherwise an "invalid number" error at the `-`.
- With `allow_nan=False` (the default) nothing changes: `NaN` and `Infinity` are invalid literals at their first letter, and `-Infinity` is an invalid number at the `-`.
- `loads` passes `allow_nan` to the scanner.
- `dumps(..., allow_nan=True)` writes a nan as `NaN`, positive infinity as `Infinity` and negative infinity as `-Infinity`. With `allow_nan=False` they still raise `ValueError`.
