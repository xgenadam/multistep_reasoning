Write a command-line tool `logscan.py` that prints the lines of a log file at a given level.

Usage: `python logscan.py PATH LEVEL [--at-least] [--limit N]`. The options may come before or after the positional arguments.

The log format: each line is `DATE TIME LEVEL MESSAGE`, for example `2026-03-14 09:26:53 WARN disk 91% full`. The level is the third whitespace-separated field of the line, and the known levels are `INFO`, `WARN` and `ERROR`, ordered `INFO < WARN < ERROR`. A line whose third field is not exactly one of those three uppercase words, or that has fewer than three fields, has no level and never matches. The level words appearing anywhere else in a line (inside the message, for instance) do not count.

Behaviour:
- LEVEL on the command line is one of the three level names in any letter case (`warn`, `Warn` and `WARN` are the same). Any other value is a usage error: a message containing `usage` on standard error and exit status 2.
- A line matches if its level equals LEVEL. With `--at-least`, a line matches if its level is LEVEL or higher.
- Matching lines are printed to standard output in file order, each exactly as it appears in the file, followed by a newline (also for a last line that had no trailing newline in the file).
- `--limit N` prints at most the first N matching lines. N must be an integer of 0 or more, otherwise it is a usage error (exit status 2, as above).
- After the lines, print exactly one line `count=M` to standard error, where M is the number of matching lines in the whole file, even when `--limit` stopped the printing early. Exit with status 0, even when nothing matched.
- PATH is read as UTF-8. If PATH does not exist or is not a regular file, print `logscan.py: cannot open PATH` to standard error (with PATH as given), print nothing else, and exit with status 1.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
