Write a small persistent key-value store as the package `kv/`, in four files: `kv/__init__.py`, `kv/log.py`, `kv/store.py` and `kv/compact.py`. Every write goes to an append-only write-ahead log; a snapshot file plus compaction keeps the log short, and reopening the store after a crash recovers everything that was fully written. Keys and values are `bytes`. All integers in the file formats are unsigned big-endian, and every checksum is `zlib.crc32(...)` (as an unsigned 32-bit value).

## Errors

In `kv/log.py`: `KVError(Exception)` and `CorruptLog(KVError)`, which has an attribute `offset` (the byte offset where the bad record starts). In `kv/compact.py`: `CorruptSnapshot(KVError)`.

## `kv/log.py`: the write-ahead log

Constants `PUT = 1` and `DELETE = 2`. `Record` is a `typing.NamedTuple` with the fields `op: int`, `key: bytes`, `value: bytes`.

A record on disk is laid out as:

| Bytes | Field |
| --- | --- |
| 4 | `crc`: `zlib.crc32` of the `length` field and the payload (every byte of the record after `crc`) |
| 4 | `length`: the number of payload bytes |
| `length` | the payload: `op` (1 byte), `key_len` (2 bytes), the key, then the value |

A `DELETE` record has an empty value.

- `encode_record(op, key, value=b'') -> bytes` builds one record. It raises `TypeError` if `key` or `value` is not `bytes`, and `ValueError` if `op` is not `PUT` or `DELETE`, if the key is empty or longer than 65,535 bytes, or if a `DELETE` has a value.
- `decode_records(data: bytes) -> tuple[list[Record], int]` reads records from the start of `data` and returns them with `valid_end`, the offset just after the last good record. It stops without error at a *torn tail*, which is the remnant of a write interrupted by a crash:
  - fewer than 8 bytes left for the `crc` and `length` fields; or
  - a `length` that runs past the end of `data`; or
  - a checksum mismatch in a record that ends exactly at the end of `data`.

  It raises `CorruptLog` for damage anywhere else:
  - a checksum mismatch in a record followed by more bytes;
  - a record with a correct checksum whose payload is malformed. Malformed means shorter than 3 bytes, an unknown `op`, a `key_len` of 0 or larger than the bytes left, or a `DELETE` with a value.

`Log(path)` is the open log file:
- Opening creates the file if it does not exist, reads it with `decode_records` and truncates the file on disk to `valid_end`, so that a torn tail is discarded before anything new is appended. A `CorruptLog` propagates out of the constructor.
- Attributes: `recovered` (the list of records read at open), `truncated` (how many bytes were cut off at open, 0 if none), `count` (records now in the file) and `size` (bytes now in the file).
- `append(op, key, value=b'') -> int` encodes and writes one record at the end of the file, flushes it, and returns the offset where it starts.
- `reset()` empties the file (count and size become 0), and `close()` closes it.

## `kv/compact.py`: snapshots

A snapshot file holds the whole data set:

| Bytes | Field |
| --- | --- |
| 4 | the magic `b'KVS1'` |
| 4 | `count`: the number of entries |
| per entry, sorted by key | `key_len` (2 bytes), the key, `value_len` (4 bytes), the value |
| 4 | `crc`: `zlib.crc32` of every byte before it |

- `encode_snapshot(items: dict[bytes, bytes]) -> bytes` and `decode_snapshot(data: bytes) -> dict[bytes, bytes]`. Decoding raises `CorruptSnapshot` for a wrong magic, a checksum mismatch, data that ends early, or bytes left over after the entries and checksum.
- `write_snapshot(path, items)` writes atomically: it writes the bytes to `path + '.tmp'`, flushes them, then renames that file over `path` with `os.replace`.
- `read_snapshot(path) -> dict[bytes, bytes]` returns `{}` if the file does not exist.
- `compact(snapshot_path, items, log)` writes the snapshot first and only then calls `log.reset()`. A crash between the two leaves an old log on top of a snapshot that already includes it, so replaying that log again gives the same data.

## `kv/store.py`

`KVStore(directory, max_log_records=None)`:
- Opening creates the directory if needed and uses two files in it, `snapshot.db` and `wal.log`. It deletes a leftover `snapshot.db.tmp` (an interrupted snapshot write) if there is one. Then it loads the snapshot, opens the log with `Log`, and replays the recovered records over the snapshot in order. `CorruptLog` and `CorruptSnapshot` propagate.
- `put(key, value)` appends a `PUT` record and then updates the data; it writes a record even if the value is unchanged. Keys and values are checked as in `encode_record`.
- `get(key, default=None)`, `key in store` and `len(store)`.
- `delete(key) -> bool` appends a `DELETE` record and returns `True` if the key existed. Deleting a missing key writes nothing and returns `False`.
- `scan(start=None, end=None, prefix=b'') -> list[tuple[bytes, bytes]]`: the `(key, value)` pairs with `start <= key < end` (either bound may be `None` for no limit) whose key starts with `prefix`, sorted by key.
- `compact()` calls `compact.compact` with the current data. When `max_log_records` is set, a `put` or `delete` that leaves the log with more than `max_log_records` records compacts automatically, right after that write.
- `stats() -> dict` returns `{'keys': ..., 'log_records': ..., 'log_bytes': ...}` for the current data and log.
- `close()` closes the log; after it, `put`, `get`, `delete`, `scan`, `compact` and `stats` raise `KVError`. The store is a context manager that closes on exit.

`kv/__init__.py` re-exports `KVStore`, `KVError`, `CorruptLog`, `CorruptSnapshot`, `Log`, `Record`, `PUT`, `DELETE`, `encode_record`, `decode_records`, `encode_snapshot`, `decode_snapshot`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
