Extend `sudoku.py` with step-by-step hints and a difficulty rating based on them. Everything from the previous version keeps working exactly as before.

The *candidates* of an empty cell are the digits 1–9 that do not appear in its row, its column or its 3×3 box. Box `b` (0–8) covers rows `3*(b//3)` to `3*(b//3)+2` and columns `3*(b%3)` to `3*(b%3)+2`.

- `hint(grid) -> tuple[int, int, int, str] | None` returns the next logical step as `(row, col, digit, reason)`, with 0-based `row` and `col`. It looks for steps in this order and returns the first it finds:
  1. **Naked single:** scanning the empty cells in row-major order (row 0 left to right, then row 1, and so on), the first cell with exactly one candidate. The reason is `'naked single'`.
  2. **Hidden single:** going through the units in the order rows 0–8, then columns 0–8, then boxes 0–8, and within each unit through the digits 1–9 in increasing order, the first digit that is not yet in the unit and is a candidate of exactly one empty cell of the unit. The reason is `'hidden single in row'`, `'hidden single in column'` or `'hidden single in box'`, after the kind of unit.

  It returns `None` if neither kind of step exists (including for a complete grid). It raises `ValueError` if the grid has a bad shape (as before) or is not valid. It never modifies the grid.
- `difficulty(grid) -> dict[str, int] | None` works on a copy of the grid: it repeatedly takes `hint`, writes the digit into the cell, and repeats until the grid is complete. It returns `{'naked': N, 'hidden': H}`, the number of steps of each kind that were used, or `None` if at some point the grid is not complete and `hint` returns `None` (the puzzle needs guessing or has no solution). A complete valid grid gives `{'naked': 0, 'hidden': 0}`. It raises `ValueError` like `hint` and never modifies its argument.

Use only the Python 3.12 standard library. Give the complete updated files, each in its own fenced code block, with the file's path on the line just before the block.
