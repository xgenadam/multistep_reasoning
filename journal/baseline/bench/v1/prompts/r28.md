Write an explainer of Dijkstra's shortest-path algorithm for second-year computer science students who know graphs and priority queues but haven't met the algorithm yet. Work through this undirected graph, where each weight is a distance, with A as the source:

A-B 4, A-C 2, B-C 1, B-D 5, C-D 8, C-E 10, D-E 2, D-F 6, E-F 3

Use these markdown sections: How the algorithm works, The example graph, Step-by-step trace, Final distances and paths, Common mistakes.

- How the algorithm works: the idea, the steps, and why it needs non-negative edge weights.
- Step-by-step trace: a table with one row for the initial state and then one row per node settled (seven rows below the header), with a column for the node settled and a column for the tentative distance to each of A to F after that step (write ∞ for unknown). Below the table, point out each relaxation that improved an already-known distance. If two nodes ever tie for the smallest tentative distance, settle the alphabetically first one.
- Final distances and paths: a table with the columns Node, Distance from A and Shortest path (written like A → C), one row per node.
- Common mistakes: exactly three mistakes students make, as bullet points.

Be precise, but write for students learning it, not for experts. Aim for about 800-1,000 words.
