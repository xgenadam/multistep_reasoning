Write a Python module `semver.py` for Semantic Versioning 2.0.0 version numbers and simple version ranges.

`class Version`:
- `Version.parse(text: str) -> Version` parses a full version `MAJOR.MINOR.PATCH`, optionally followed by `-PRERELEASE` and then optionally `+BUILD`, exactly as the SemVer 2.0.0 specification defines them: MAJOR, MINOR and PATCH are non-negative integers without leading zeros; PRERELEASE and BUILD are non-empty dot-separated identifiers of `[0-9A-Za-z-]`; a numeric pre-release identifier must not have leading zeros (build identifiers may). Anything else raises `ValueError`, including a leading `v`, surrounding whitespace, missing parts (`1.2`), and empty identifiers (`1.2.3-`, `1.2.3-a..b`).
- Attributes: `major`, `minor`, `patch` (ints), `prerelease` and `build` (tuples of identifier strings, empty when absent). `Version.parse('1.2.3-rc.1+exp.7').prerelease == ('rc', '1')`.
- `str(v)` gives the canonical text, which for a parsed version is the text it was parsed from.
- Comparison operators (`<`, `<=`, `>`, `>=`, `==`, `!=`) follow SemVer precedence: compare MAJOR, MINOR and PATCH numerically; a version with a pre-release is lower than the same version without one; pre-release identifiers are compared left to right, numeric identifiers numerically, alphanumeric ones in ASCII order, numeric lower than alphanumeric, and a shorter list lower when all earlier identifiers are equal. Build metadata is ignored, so `Version.parse('1.0.0+a') == Version.parse('1.0.0+b')`, and `hash()` agrees with `==`. Comparing with a non-`Version` returns `NotImplemented`.
- `v.bump(kind) -> Version` returns a new version: `'major'` gives `(MAJOR+1).0.0`, `'minor'` gives `MAJOR.(MINOR+1).0`, `'patch'` gives `MAJOR.MINOR.(PATCH+1)`. The result never has a pre-release or build part, so `1.2.3-rc.1` bumped by `'patch'` is `1.2.4`. Any other kind raises `ValueError`.

`satisfies(version, spec: str) -> bool`, where `version` is a `Version` or a version string:
- `spec` is one or more comparators separated by whitespace, and the version must satisfy all of them.
- In a comparator, a version may be partial: `1` means `1.0.0` and `1.2` means `1.2.0`. A partial version cannot have a pre-release or build part.
- `>=V`, `>V`, `<=V`, `<V` and `=V` compare by precedence; a bare `V` means `=V`.
- `^V` allows changes that do not modify the left-most non-zero part of `MAJOR.MINOR.PATCH`: `^1.2.3` is `>=1.2.3 <2.0.0`, `^0.2.3` is `>=0.2.3 <0.3.0`, `^0.0.3` is `>=0.0.3 <0.0.4`, and a partial `^1.2` is `^1.2.0`.
- `~V` allows patch-level changes: `~1.2.3` is `>=1.2.3 <1.3.0`, `~1.2` is `>=1.2.0 <1.3.0`, and `~1` is `>=1.0.0 <2.0.0`.
- Pre-release versions get no special treatment: they are compared by plain precedence, so `2.0.0-rc.1` satisfies `^1.2.0` and `1.2.3-beta` does not satisfy `>=1.2.3`.
- An empty or malformed `spec`, or an invalid version string, raises `ValueError`.

Use only the Python 3.12 standard library. Give each file in its own fenced code block, with the file's path on the line just before the block.
